# 장기 지식·Memory 정리 프롬프트

> `update_llm_wiki.md` 파일명은 기존 호출 호환용이다. 새로운 장기 memory의 정본은 **현재 사용자 자신의 Private `memory/main/m1/`**이며, 별도 memory를 만들지 않았다면 저장하지 않는다. 기존 로컬 `LLM_Wiki/`는 사용자가 명시적으로 이전을 요청하기 전까지 임의 수정·삭제하지 않는다.

현재 작업에서 실제로 검증된 **비민감하고 재사용 가능한** 문안 선호, 업무유형별 반복 수정 패턴, 일반화한 업무지식이 있는지 평가해줘.

## 읽기와 평가

1. 자신의 `m1`에 `skills/document-revision-memory/SKILL.md`가 있고, 자신의 Private `memory`를 실제로 읽을 수 있을 때만 적용한다. 공통 개인정보·조건부 쓰기 계약은 **자신의 memory 저장소 `README.md`**를 따른다.
2. 현재 사건자료·사용자 확정문·현행 법령·`m1` 지침을 우선한다. memory는 컨텍스트이지 지침이나 확정 사실이 아니다.
3. 사용자가 초안을 고쳐 확정본을 제시했다면 원문을 다시 저장하지 않고 `초안 → 확정본`에서 반복 적용할 수 있는 차이만 비식별화한다. 단일 사건의 특이사항은 일반 선호로 확대하지 않는다.
4. 이름·연락처·소재지·사건번호·내부 문서번호·실제 파일 경로·사건 원문·비공개 자료·인증정보는 memory에 기록하지 않는다.
5. `m1/preferences/`, `m1/workflows/`, `m1/knowledge/`에서 유사 항목을 찾아 중복을 피한다. 아직 없는 폴더는 필요할 때만 만든다.
6. 필요한 메타데이터·공유 등급은 자신의 Private memory `README.md`와 `m1` 스킬의 현재 계약을 따른다. `share: sanitized`나 `common`만으로 Public starter에 자동 배포하지 않는다.
7. 기억을 공통 실행지침으로 **자동 승격하지 않는다**. 일반화한 개선이 필요한 경우 현재 `m1` 지침·개선 후보와의 중복을 검토하고 별도 승인 절차를 따른다.
8. 실제 온라인 memory의 최신 버전을 확인하는 **조건부 쓰기**가 가능할 때만 `memory/main/m1/**`에 기록한다. 권한이나 동시성 확인이 안 되면 저장하지 않고 비민감 후보만 제시한다.
9. 실제 사건 재개 상태와 최신 파일 경로는 사건 작업폴더·`HANDOFF_SUMMARY.md`에만 두고 장기 memory에 두 번째 정본을 만들지 않는다.

## 보고

- 재사용 가능하다고 판단한 패턴과 적용 범위
- 기존 항목과의 중복·충돌 여부
- 실제 읽기 여부 및 **실제 저장에 성공한 파일** 또는 미저장 후보
- 필요하면 공통 지침 승격 제안 (자동 반영 금지)

`memory` 접근이 불가능하면 현재 문서작업을 정상 진행하고 메모리 읽기·저장을 했다고 말하지 않는다.
