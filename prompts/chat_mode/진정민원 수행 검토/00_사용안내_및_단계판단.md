# 진정민원 Chat 모드 사용 안내 및 단계판단

## 1. 적용 범위

감사·민원부서에서 처리하는 진정민원의 단계와 현재 산출물을 구분하기 위한 Chat 모드 안내이다.

현재 자료 상태와 산출물에 따라 다음 두 경로를 구분한다.

| 단계 | 자료 상태 | 기본 산출물 |
|---|---|---|
| 진정민원 1단계 | 현재 진정민원과 필요한 기존 수·발신 자료는 있으나, 담당부서의 이번 해소계획 회신은 아직 없음 | 민원내용 검토 + `< 민원 내용 및 요청사항 정리 >` 초안 |
| 진정민원 2단계 | 담당부서의 해소계획 회신 또는 관련 증빙이 도착함 | 쟁점별 회신·증빙 검토 + 필요한 보완 + 민원인 회신 답변서 초안 |

1단계는 담당부서가 답해야 할 사실·근거·기록·조치계획을 구체화하는 단계이고, 2단계는 도착한 회신과 증빙을 검증하여 부족한 부분을 보완하고 민원인에게 근거 있는 결론을 설명하는 단계이다. 1단계 요청문 구조를 2단계 회신문 형식으로 재사용하지 않는다.

## 2. 다른 업무와의 경계

- 국민권익위원회·도권익위원회 고충민원 1·2·3·4단계 → `prompts/chat_mode/권익위 수행 검토/`
- 공익신고 대상성·조사요청·조사결과 통보 → `prompts/chat_mode/공익신고 검토/`
- 단순 일반민원 회신문 작성 → `admin-document-base-review`
- 진정민원 접수 후 담당부서 해소계획 제출 요청 → `진정민원 1단계`
- 담당부서 해소계획 회신·증빙 도착 후 검토 및 민원인 회신 답변서 작성 → `진정민원 2단계`

문서 제목에 `고충민원`, `진정`, `감사 요청` 등의 표현이 있다는 이유만으로 자동 적용하지 않는다. 현재 자료 상태와 업무 목적을 기준으로 1단계인지 2단계인지 판별한다. 외부 권익기관의 요청에 따른 설명자료 제출·처리결과 통보는 담당부서 회신이 있더라도 이 2단계가 아니다.

## 3. Chat 모드 경계

- 사건 사실은 현재 대화에 첨부·붙여넣기 된 자료와 사용자가 확정한 사항만 사용한다.
- GitHub 저장소에서 사건자료를 찾지 않는다.
- 단계별 구조를 재사용할 때는 `skills/petition-resolution-plan-workflow/templates/SAMPLE_CATALOG.md`와 카탈로그에서 선택한 비식별 샘플을 실제로 읽는다.
- HWP/HWPX 자체 수정·생성이 필요하지 않으면 Markdown 초안을 먼저 제공한다.
- 읽지 못한 자료, 확인하지 않은 법령, 존재를 확인하지 못한 문서를 확인했다고 표현하지 않는다.

## 4. 읽을 정본

### 4.1 진정민원 1단계

1. `skills/petition-resolution-plan-workflow/SKILL.md`
2. `skills/petition-resolution-plan-workflow/references/stage1_department_resolution_plan_request.md`
3. `skills/petition-resolution-plan-workflow/templates/SAMPLE_CATALOG.md`
4. 카탈로그의 active 1단계 샘플

공통 행정문서 판단이 더 필요하면 `admin-document-base-review`와 `guides/BASE_INSTRUCTIONS.md`의 관련 절만 추가 확인한다.

### 4.2 진정민원 2단계

1. `skills/petition-resolution-plan-workflow/SKILL.md`
2. `skills/petition-resolution-plan-workflow/references/stage2_department_reply_review.md`
3. `prompts/chat_mode/진정민원 수행 검토/02_2단계_담당부서_회신검토_및_민원인답변.md`
4. `skills/petition-resolution-plan-workflow/templates/SAMPLE_CATALOG.md`
5. 카탈로그에서 현재 사건 구조에 맞게 선택한 2단계 샘플

작성 전에는 `document-validation-pipeline`에 준하는 구조화 검증을 한 번 수행하고, 초안 작성 후에는 그 검증결과와의 일치만 간단히 확인한다.

## 5. 자료 사용 순서

### 내용 근거

1. 사용자의 현재 확정사항
2. 이번에 접수된 진정민원 원문과 첨부자료
3. 이번 민원과 직접 연결되는 기존 수·발신 민원·회신·정보공개·확인자료
4. 담당부서·관계기관의 공식 자료

### 구조 기준 — 1단계

1. 사용자가 현재 사건에 지정한 확정 실무 서식
2. `SAMPLE_CATALOG.md`의 active 구조 예시

샘플은 사건 사실이나 책임 판단의 근거가 아니다.

### 구조 기준 — 2단계

1. 사용자가 현재 사건에 지정한 확정 답변서 서식
2. `SAMPLE_CATALOG.md`의 2단계 기본 또는 조건부 구조 예시

담당부서 회신과 샘플은 각각 증빙과 구조 참고자료일 뿐이다. 회신 문구만으로 사실을 확정하지 않고, 샘플에서 사건 사실이나 법적 판단을 가져오지 않는다.

## 6. 1단계 기본 판단

- 현재 민원이 신규 쟁점인지, 기존 민원의 연속·재제기인지 구분한다.
- 민원인의 주장, 기존 담당부서 설명, 확인된 사실, 이번에 담당부서로부터 확인해야 할 사항을 분리한다.
- 독립 쟁점을 중복이라는 이유로 삭제하지 않고, 담당부서가 답할 사항과 감사·민원부서 자체 확인사항, 다른 부서·기관 소관사항을 구분한다.
- 기존 민원 전부를 요약하지 말고 이번 해소계획 회신에 필요한 경위만 남긴다.
- 이미 확인된 사실을 단순 재질의하지 않는다.
- `제대로 검토했는지`가 쟁점이면 추상적으로 묻기보다 당시 검토보고서·내부결재자료·업무메모·협의자료 등 확인 가능한 기록 또는 구체적인 검토경위를 묻는다.
- 기존 회신에서 후속조치를 예고했다면 현재 진행상황을 확인한다.
- 감사부서가 기존 답변의 부실·위법·부당을 선결론한 것처럼 쓰지 않는다.

## 7. 1단계 기본 출력

1. `현재 단계 및 사용 자료`
2. `핵심 검토결과`
3. `확인 필요사항` — 담당부서 외 별도 확인과제가 있으면 구분
4. `최종 < 민원 내용 및 요청사항 정리 > 초안`
5. `결재 전 확인사항` — 실제 확인할 항목이 있을 때만

사용자가 바로 문안만 요청하면 분석을 줄이고 초안을 먼저 제시할 수 있다.

## 8. 2단계 기본 판단과 출력

### 기본 판단

- 민원인의 독립 쟁점·요구, 1단계 확인요청, 담당부서 답변, 제출 증빙, 검증결과, 남은 조치를 쟁점별로 대조한다.
- `검토하였다`, `조치하였다` 같은 회신 문구는 관련 기록이나 결과와 대조한다.
- 결론에 중요한 누락·상충·증빙 부족은 최소 범위로 보완요청하고, 새 자료가 오면 영향을 받는 쟁점만 다시 검증한다.
- 예정·진행·완료와 기준시점을 구분하고, 담당부서·감사부서·타 기관의 권한을 넘겨 단정하지 않는다.
- 초안 작성 전에 내용 검증을 완료하고, 작성 뒤에는 검증결과와 문안의 일치만 확인한다.

### 기본 출력

1. `현재 단계 및 결정적 자료`
2. `쟁점별 회신·증빙 검토결과`
3. `보완 또는 별도 확인사항` — 필요한 경우만
4. `작성 전 검증결과`
5. `민원인 답변서 초안`
6. `결재 전 확인사항` — 실제 남은 항목만

## 9. 시작 문구

### 1단계

```text
@GitHub m1-starter의 CHATGPT_ENTRYPOINT.md에서 진정민원 1단계 경로를 적용해줘.
이번에 접수된 민원과 직접 연결되는 기존 수·발신 자료를 검토해서 담당부서에 요청할 `진정사항 관련 추진내용 및 향후 해소계획`의 `< 민원 내용 및 요청사항 정리 >` 초안을 작성해줘.
박스 외 기존 양식은 고정하고, 같은 이야기의 반복은 줄이되 독립 쟁점은 누락하지 말고, 담당부서가 실제 사실관계·검토기록·현재 조치상태를 답할 수 있도록 확인사항을 구체화해줘.
```

### 2단계

```text
@GitHub m1-starter의 CHATGPT_ENTRYPOINT.md에서 진정민원 2단계 경로를 적용해줘.
이번 민원, 1단계 해소계획 요청, 담당부서 회신과 증빙을 쟁점별로 대조하고, 답변 누락·근거 부족·상충 여부와 보완 필요성을 먼저 검증해줘.
그 검증결과를 기준으로 현재 사건의 확정 서식을 우선하여 민원인 답변서 초안을 작성하고, 샘플은 구조 참고로만 사용해줘.
```
