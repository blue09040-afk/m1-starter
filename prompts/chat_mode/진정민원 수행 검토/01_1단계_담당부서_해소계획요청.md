# Chat 모드 프로젝트 소스용 진정민원 1단계 담당부서 해소계획 요청 지침

> 용도: 진정민원 접수 후 현재 민원내용과 필요한 기존 수·발신 자료를 검토하여 담당부서에 `진정사항 관련 추진내용 및 향후 해소계획` 제출을 요청하는 초안을 작성할 때 적용한다.

## 1. 적용 조건

다음 조건을 모두 충족하는 경우에 적용한다.

- 현재 진정민원이 접수되어 있음
- 담당부서의 이번 해소계획 회신은 아직 없음
- 사용자가 민원내용 검토와 담당부서 해소계획 요청 초안 작성을 요구함
- `진정사항 관련 추진내용 및 향후 해소계획` 서식을 사용함

권익위 고충민원 1·2·3단계나 공익신고 업무에는 적용하지 않는다.

담당부서의 해소계획 회신과 관련 증빙이 이미 도착했다면 `진정민원 2단계(예정)`로 구분한다. 2단계는 담당부서 회신내용을 검토하고 민원인 회신 답변서를 작성하는 단계이며, 별도 세부 지침이 마련되기 전까지 이 1단계 지침을 기계적으로 적용하지 않는다.

## 2. 작성 전 확인

1. 이번 접수 민원 원문과 첨부자료를 확인한다.
2. 사용자가 제공한 기존 수·발신 자료 중 이번 민원과 직접 연결되는 것만 대조한다.
3. 현재 민원이 기존 민원의 연속·재제기인지, 새로운 쟁점이 추가되었는지 구분한다.
4. 각 쟁점이 현재 담당부서가 답할 사항인지, 감사·민원부서 자체 확인사항인지, 다른 부서·기관 소관인지 구분한다.
5. 사용자가 지정한 최신 `진정사항 관련 추진내용 및 향후 해소계획` 서식을 기준본으로 확인한다.
6. `skills/petition-resolution-plan-workflow/templates/SAMPLE_CATALOG.md`와 active 구조 예시를 실제로 읽는다.

자료가 부족해도 가능한 범위의 잠정 초안을 먼저 제시하되, 결과를 크게 바꾸는 누락만 최대 3개까지 질문한다.

## 3. 최우선 형식 규칙

### 3.1 박스 외 양식 고정

사용자가 별도 수정을 요청하지 않으면 `< 민원 내용 및 요청사항 정리 >` 외 부분은 고정 양식으로 취급한다.

- `○ 발생 배경`
- `○ 진정(민원) 내용`
- `○ 진정민원 관련 추진경위`
- `□ 진정 내용의 사실여부 및 경과 등`
- `(민원인 주장) / (답변)`
- 수사·재판·처분 등 사항
- `□ 민원해소를 위한 향후 조치계획 등`
- 확인자·작성자·감사관 귀하·주의문구

중복을 줄이거나 문체를 다듬는다는 이유로 이 부분을 다시 설계하지 않는다.

### 3.2 박스 안만 사건별로 작성

`< 민원 내용 및 요청사항 정리 >`에는 다음만 필요한 범위에서 작성한다.

1. 민원 대상과 핵심 쟁점 제목
2. 이번 민원의 핵심 문제 제기
3. 현재 쟁점 이해에 필요한 기존 처리·회신 경위
4. 담당부서 확인이 필요한 구체적인 사실·판단근거·관련 기록
5. 기존 회신에서 예고한 후속조치가 있다면 현재 진행상황
6. 제출 요청 문장

## 4. 민원 내용 압축 기준

- 민원인의 같은 주장이 여러 문단·여러 기존 민원에 반복되면 한 번만 정리한다.
- 기존 회신 전문을 재현하지 않는다. 이번 확인사항을 이해하는 데 필요한 내용만 남긴다.
- 민원인의 요구사항을 전부 나열하는 것이 아니라, 담당부서가 이번 해소계획에서 답해야 할 핵심 쟁점을 중심으로 압축한다.
- 다만 향후 민원인 회신에서 별도로 답할 필요가 있는 독립 쟁점을 `중복`이라는 이유로 삭제하지 않는다. 담당부서 요청 대상이 아니면 감사·민원부서 자체 확인사항 또는 다른 부서·기관 소관으로 분리한다.
- 하단 고정 양식에서 담당부서가 다시 작성할 `발생 배경`, `추진경위`, `사실 여부`, `향후 계획`을 박스 안에서 미리 상세히 쓰지 않는다.

## 5. 확인사항 설계 기준

### 5.1 담당부서 소관과 별도 확인사항 구분

담당부서에는 그 부서가 실제 업무처리 사실·판단근거·후속조치를 설명할 수 있는 사항만 요청한다.

- 감사·민원부서의 배부·감사·처리경위 자체가 쟁점이면 자체 확인사항으로 분리
- 다른 부서 또는 다른 기관의 권한·처리가 쟁점이면 해당 소관으로 분리
- 담당부서 요청에서 제외한 독립 쟁점은 필요하면 별도 확인과제로 남김

### 5.2 이미 확인된 사실의 반복 질의 금지

공식자료 또는 사용자가 직접 확인한 신뢰 가능한 자료에서 존재 여부가 확인된 사항을 담당부서에 다시 확인시키는 질문은 원칙적으로 넣지 않는다.

그 질문이 새로운 사실을 만들어내지 못하면 다음처럼 바꾼다.

- 자료의 존재가 확인됨 → 존재 여부가 아니라 당시 판단에 관한 구체적인 검토근거·기록 여부를 확인
- 담당부서가 과거 자료를 안내함 → 단순 `참조했는지`보다 실제 판단과정을 확인할 수 있는 기록이 있는지 확인

### 5.3 `제대로 검토했는지`를 직접 묻지 않기

추상적인 적정성 질문은 방어적인 일반론을 유도하기 쉽다. 검토의 실재성과 과정을 확인하려면 사건에 필요한 범위에서 다음을 확인한다.

- 현장 확인 실시 여부, 일시·방법·확인 내용
- 분석·모니터링의 방법과 구체적 판단근거
- 검토보고서, 내부결재자료, 업무메모, 출장기록, 관계기관 협의자료, 기술자문 자료 등 당시 판단과정을 확인할 수 있는 문서·기록의 작성·보유 여부

사건 쟁점과 무관한 자료까지 포괄적으로 요구하지 않는다.

### 5.4 예정 조치의 현재 상태 확인

기존 회신에서 기술자문, 관계기관 협의, 현장점검, 개선조치 등을 예정했다고 안내한 경우, 현재 진행 여부와 향후 계획을 확인한다. 완료된 사실을 계획으로 쓰거나 예정 상태를 완료로 단정하지 않는다.

## 6. 감사부서 문체 기준

- 민원인의 문제 제기는 `민원인은 ... 문제를 제기하고 있음`으로 귀속한다.
- 사실확인이 필요한 부분은 `... 확인할 필요가 있음`으로 정리할 수 있다.
- 기존 회신이 부실·형식적·위법·부당하다고 감사부서가 미리 판단한 것처럼 쓰지 않는다.
- `기존 회신 내용을 단순 반복하지 말라`, `부실 답변을 보완하라` 등 질책성 문구는 넣지 않는다.
- 필요한 구체성은 평가적 표현이 아니라 확인할 사실과 자료를 정확히 특정하여 확보한다.

## 7. 기본 문안 구조

```text
< 민원 내용 및 요청사항 정리 >

□ <민원 대상과 핵심 쟁점 제목>

  ○ <이번 민원의 핵심 문제 제기>

  ○ <현재 쟁점 이해에 필요한 기존 처리·회신 경위 — 필요한 경우>

  ○ <현재까지 구체적인 확인이 필요한 사항>

     - <확인항목 1>
     - <확인항목 2>
     - <확인항목 3>

  ○ <기존 회신에서 예고한 후속조치의 현재 진행상황 확인 — 필요한 경우>

  → 위 사항과 관련하여 실제 업무처리 내용 및 관련 자료를 기준으로 구체적으로 작성하여 제출하여 주시기 바랍니다.
```

문단·하위항목 수는 고정하지 않는다. 사건별로 필요한 최소 수만 사용한다.

## 8. 출력 형식

사용자가 다른 형식을 지정하지 않으면 다음 순서로 답한다.

1. `현재 단계 및 자료 신뢰도`
2. `핵심 검토결과`
3. `최종 < 민원 내용 및 요청사항 정리 > 초안`
4. `확인 필요사항` — 담당부서 외 별도 확인과제 또는 실제 남아 있는 사항이 있을 때만

사용자가 `굵은 수정안`을 함께 요청하면 이 지침으로 내용을 먼저 안정화한 뒤 `굵은_수정안_검토_지침.md`를 적용한다.
사용자가 `반복 재검토`를 함께 요청하면 먼저 반복 재검토로 내용을 안정화한 후 필요한 경우 굵은 수정안을 적용한다.

- [ ] 이번 민원과 직접 관계없는 과거 민원까지 끌어오지 않았는가?
- [ ] 같은 문제 제기와 확인항목을 반복하지 않았는가?
- [ ] 독립 쟁점을 중복이라는 이유로 누락하지 않았는가?
- [ ] 담당부서 요청사항과 감사·민원부서 자체 확인사항, 타 부서·기관 소관사항을 구분했는가?
- [ ] 이미 확인된 사실을 의미 없이 다시 묻지 않았는가?
- [ ] `제대로 검토했는지` 같은 추상 질문을 확인 가능한 사실·기록으로 바꾸었는가?
- [ ] 예정·진행·완료 상태를 구분했는가?
- [ ] 담당부서를 질책하거나 책임을 선결론하는 문구가 없는가?
- [ ] 사건자료에 없는 문서·근거·책임을 만들어내지 않았는가?
- [ ] 개인정보·내부정보를 필요한 범위 이상 옮기지 않았는가?
