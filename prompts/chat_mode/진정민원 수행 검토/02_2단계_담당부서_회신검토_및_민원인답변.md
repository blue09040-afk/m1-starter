# Chat 모드 프로젝트 소스용 진정민원 2단계 담당부서 회신 검토 및 민원인 답변 지침

> 용도: 1단계 해소계획 요청에 대한 담당부서 회신 또는 관련 증빙이 도착한 뒤, 회신의 충실성과 근거를 검토하고 필요한 보완을 거쳐 민원인 답변서 초안을 작성할 때 적용한다.

## 1. 적용 조건과 경계

다음 조건을 모두 충족하는 경우에 적용한다.

- 진정민원 1단계에서 담당부서의 추진내용·향후 해소계획을 요청함
- 담당부서 회신 또는 관련 증빙이 현재 대화에 제공됨
- 사용자가 회신 검토, 보완사항 도출 또는 민원인 답변서 작성을 요청함

담당부서 회신이 일부만 도착했어도 1단계로 되돌리지 않고 2단계 보완 절차를 적용한다. 국민권익위원회·도권익위원회 요청에 따른 외부기관 설명자료 제출·처리결과 통보에는 적용하지 않는다.

## 2. 반드시 읽을 자료

1. `skills/petition-resolution-plan-workflow/SKILL.md`
2. `skills/petition-resolution-plan-workflow/references/stage2_department_reply_review.md`
3. `skills/petition-resolution-plan-workflow/templates/SAMPLE_CATALOG.md`
4. 카탈로그에서 선택한 2단계 비식별 구조 예시
5. 현재 대화에 제공된 이번 민원, 1단계 요청문, 담당부서 회신과 증빙

사건 사실을 GitHub `m1`에서 찾지 않는다. 읽지 못한 파일이나 확인하지 않은 법령·증빙을 확인했다고 표현하지 않는다.

## 3. 작성 전 쟁점별 검토

각 독립 쟁점마다 다음을 대조한다.

| 쟁점·요구 | 기존 처리·후속약속 | 1단계 확인요청 | 담당부서 답변 | 증빙 | 검증결과 | 남은 조치 | 답변 반영 |
|---|---|---|---|---|---|---|---|
| <쟁점> | <필요한 경위> | <질문> | <회신> | <자료> | 확인/일부/상충/미확인 | 보완/자체확인/타기관/답변가능 | <결론·한계·조치> |

회신 문단 수에 맞춰 민원 쟁점을 합치지 않는다. 담당부서의 설명과 증빙으로 확인된 사실을 구분하고, 증빙이 없다는 이유만으로 사실이 존재하지 않는다고 단정하지 않는다.

## 4. 회신·증빙 충실성 검사

- 1단계 핵심 질문에 실제로 답했는가
- 필요한 사실, 방법, 근거, 기준시점과 조치상태가 구체적인가
- `검토·조치·문제없음`이라는 결론을 뒷받침하는 기록이 있는가
- 회신, 첨부자료, 기존 회신, 공식자료 사이에 모순이 없는가
- 예정·진행·완료·미실시를 구분했는가
- 담당부서가 설명할 권한과 자료 범위를 넘겨 단정하지 않았는가
- 민원인의 모든 독립 요구에 답할 수 있는가

수치가 결론에 영향을 주면 단위·산식·집계기간·기준일을 확인하고 가능한 범위에서 재계산한다. 이미지·영상·녹음·OCR 등은 판독 신뢰도와 원맥락을 확인한다.

## 5. 보완 판단

핵심 쟁점 누락, 결론적 일반론, 결정적 증빙 부재, 자료 간 상충, 후속조치 상태 불명확이 결론을 바꿀 수 있으면 필요한 최소 범위로 보완요청안을 작성한다. `부실 회신`처럼 평가하지 말고 필요한 사실·시점·자료를 특정한다.

주변적 누락이거나 미확인 한계를 밝혀도 핵심 답변이 달라지지 않으면 현재 자료 기준으로 답변할 수 있다. 새 자료가 오면 영향을 받는 쟁점과 그에 의존하는 결론만 다시 검증한다.

## 6. 작성 전 검증 관문

민원인 답변서 초안 전에 다음을 한 번 검증한다.

1. 원자료와 요약의 대응
2. 독립 쟁점·요구 전체 포괄 여부
3. 회신·증빙의 쟁점별 충족 여부
4. 상충·누락·미확인과 보완 필요성
5. 담당부서·감사부서·타 기관의 권한 경계
6. 결론과 법적 평가의 근거 수준
7. 선택한 답변서 구조의 적합성

일반 Chat에서는 검증결과를 응답 안에 구조화해 제시한다. 파일을 만들거나 저장했다고 가정하지 않는다.

## 7. 답변서 작성

현재 사건의 확정 서식이 있으면 우선한다. 없으면 카탈로그에서 다음 순서로 선택한다.

1. 기존 처리 재점검형 — 기본
2. 단순 사실확인형 — 단일 쟁점
3. 현황 집계·복수부서형 — 여러 회신 주체의 현황 집계와 쟁점별 통합
4. 복수쟁점·권한한계형 — 여러 주장과 권한 또는 법적 효력의 한계

민원인의 주장은 귀속하고, 확인된 사실·담당부서 설명·감사부서 판단·향후조치를 구분한다. `현재까지 제출된 자료와 추가 확인 결과`처럼 기준시점을 드러내고, 미확인·권한 밖 사항은 한계와 가능한 별도 절차를 안내한다.

## 8. 출력 형식

사용자가 다른 형식을 지정하지 않으면 다음 순서로 답한다.

1. 현재 단계 및 결정적 자료
2. 쟁점별 회신·증빙 검토결과
3. 보완요청 또는 별도 확인사항 — 필요한 경우만
4. 작성 전 검증결과
5. 민원인 답변서 초안
6. 결재 전 확인사항 — 실제 남은 항목만

사용자가 바로 사용할 문안만 요청하면 내부 작업표는 줄일 수 있지만, 결론에 영향을 주는 미확인·제한사항은 남긴다.

## 9. 작성 후 확인

- 모든 독립 쟁점과 요구에 답했는가
- 검증되지 않은 사실을 확정적으로 쓰지 않았는가
- 보완 전 미확인 사항을 해결된 것처럼 쓰지 않았는가
- 근거보다 강한 위법·부당·책임 판단을 추가하지 않았는가
- 예정·진행·완료와 기준시점이 유지되었는가
- 현재 사건의 확정 서식과 선택한 구조가 맞는가

새 증빙이나 새 쟁점이 추가되지 않았다면 작성 전 검증을 반복하지 않고 문안과 검증결과의 일치만 확인한다.
