# 일상감사 공통 검토절차

## 자료 인수와 판독

1. 원자료를 수정·이동·삭제·이름변경하지 않는다.
2. 파일별 역할을 `검토대상 / 참고 / 과거버전 / 중복후보 / 판독불가`로 구분한다.
3. HWP/HWPX·PDF·스프레드시트는 형식별 판독 신뢰도를 확인한다.
4. 스프레드시트는 표시 셀뿐 아니라 숨김 시트·행·열, 수식 오류, 외부연결, 이름정의, 숫자 서식과 반올림 전 값을 확인한다.
5. 과거본·수정본·재의뢰본이 있으면 날짜와 승인상태로 기준본 후보를 정하고 담당자 확인 전 임의 확정하지 않는다.

## 핵심 사실 구조화

건명, 요청부서, 기준일, 목적·범위·기간, 금액·VAT·관급자재, 계약방법, 참가자격·업종코드, 세부품명·세부품명번호, 직접생산, 지역·중소기업 제한, 공동도급, PQ·적격심사·낙찰기준, 계약심사 및 예외사유를 자료 위치와 함께 기록한다.

판단상태는 `확정 / 잠정 / 확인 필요 / 법령 확인 필요 / 검토 제외`로 표시한다.

## 계약심사 완료 건의 범위

- 계약심사 전 금액, 조정액, 조정사유와 계약심사 계산의 적정성을 일상감사에서 다시 심사하지 않는다.
- 계약심사 결과의 **심사 후 금액**이 일상감사 의뢰서, 최종 원가·내역서, 공고안에 동일하게 반영되었는지만 확인한다.
- 심사 후 금액이 최종 문서에 반영되지 않았거나 문서 간 불일치하면 보완사항으로 제시한다.
- 계약심사 조정사유서에 확정 반영된 특허·신기술 금액과 사용료 산식을 재산정하지 않는다. 권리 유효성, 권리자, 사용협약, 공고조건, 하도급·사용료 처리 등 비금액 계약조건은 검토한다.

## 코드와 명칭 검증

- 업종명과 국가종합전자조달시스템 업종코드를 한 쌍으로 대조한다.
- 세부품명과 세부품명번호를 한 쌍으로 대조한다.
- 한 글자·한 자리 오기, 과거·폐지 코드, 실제 과업·공종·물품과의 불일치를 확인한다.
- 과거 의견서의 코드나 명칭을 복제하지 않고 공고일 적용 등록기준·분류정보를 다시 확인한다.
- 코드가 자료에 없으면 임의 생성하지 않고 `코드 병기 및 확인 필요`로 제시한다.

## 문서 간 대조 순서

1. 건명·목적·범위·수량·위치
2. 기간·착수·완료·납품 조건
3. 심사 후 금액·추정가격·VAT·관급자재
4. 계약방법·제한경쟁·공동도급
5. 참가자격·면허·업종코드·세부품명번호
6. 중소기업·직접생산·직접구매·예외
7. 낙찰기준·평가기준·하한율·점수·별표
8. 공고문 공란·오기·중복·상충

## 지적사항과 의견서

각 지적은 `상태와 중요도 → 문제 → 근거 위치 → 판단 근거와 전제 → 수정 권고문안 또는 개선안 → 추가 확인자료` 순으로 정리한다. 의견 수준은 `필수 수정 / 재검토 / 권고 / 확인 요청 / 특이사항 없음`으로 구분한다.

- `01~06`에는 사실대조, 계산·법령 확인, 미확정 쟁점, 추가자료와 담당자 확인사항을 둔다.
- `07`에는 담당자가 의견서에 바로 옮길 수 있는 문안만 둔다.
- 불확실한 사항은 `요건 확인 시 가능`, `수정 후 적용`, `확인 후 결정`, `보완 후 추진`으로 쓴다.
- 최종 의견의 사실·법령·수치·코드·표현은 담당자가 원자료 기준으로 확인한다.
