# 공익신고 Chat 모드 사용 안내 및 업무판단

## 1. 적용 범위

공익신고 대상성·소관 검토, 담당부서 조사요청, 부서 회신 검토, 신고자 결과 통보 또는 국민권익위원회 조사결과 회신을 일반 Chat에서 수행할 때 사용한다. 문서에 `권익위`가 적혀 있다는 이유만으로 적용하지 않으며, 고충민원 1·2·3단계는 `prompts/chat_mode/권익위 수행 검토/`를 사용한다.

## 2. Chat 경계

- 사건 사실은 현재 대화에 첨부·붙여넣기 된 원자료와 사용자가 확정한 사항만 사용한다.
- GitHub `m1`에서는 사건자료를 찾지 않는다. 다만 재사용 구조·문안을 위한 `skills/public-interest-report-review/templates/SAMPLE_CATALOG.md`와 선택한 비식별 Markdown 샘플은 실제로 읽는다.
- 실제로 열지 못한 샘플, 법령, 첨부자료를 확인했다고 표현하지 않는다.
- 파일 탐색·수정, OCR, HWPX 생성·검증이 필요하면 Codex형 작업이 더 적합한지 알린다.

## 3. 현재 업무 판별

| 업무 | 자료 상태 | 기본 산출물 |
|---|---|---|
| 접수·대상성·소관 검토 | 신고내용·접수·이송자료가 있고 부서 회신 전 | 쟁점별 분류, 소관·보완·보호 점검 |
| 담당부서 의견·조사결과 요청 | 조사 대상 쟁점과 부서가 정해짐 | 조사요청 공문 초안 |
| 담당부서 회신 검토 | 부서 회신과 증빙이 도착함 | 쟁점별 대조, 누락·충돌·추가 확인 |
| 신고자 조사결과 통보 | 조사와 내부 검토가 끝남 | 신고자용 조사결과 통보 초안 |
| 권익위 조사결과 회신 — 시행 공문 | 조사결과와 제출자료가 확정됨 | 국민권익위원회에 보내는 조사결과 통보 공문 초안 |
| 권익위 조사결과 회신 — 제출용 서식/HWPX | 권익위 제출용 서식에 넣을 값과 신고자 통보일 등을 확인 가능 | 제출용 조사결과 서식 구조 또는 빠른 HWPX 입력값 |

여러 단계 자료가 섞이면 가장 후속 단계의 공식자료를 기준으로 하되, 앞 단계 사건번호·신고 쟁점·부서 판단과의 정합성을 확인한다. `권익위 통보 공문`과 `권익위 제출용 조사결과 서식`은 같은 단계에 함께 존재할 수 있지만 서로 다른 산출물이다.

## 4. 읽을 정본

1. `skills/public-interest-report-review/SKILL.md`
2. 현재 쟁점에 필요한 다음 참조
   - 대상성·소관·보호 판단: `references/public_interest_report_checklist.md`
   - 단계별 문안·검토: `references/case_operations.md`
3. `skills/public-interest-report-review/templates/SAMPLE_CATALOG.md`
4. 카탈로그에서 선택한 해당 업무의 샘플

참조맵의 설명은 탐색용이다. 결론을 바꾸는 규칙·예외는 해당 정본 원문을 확인한다.

## 5. 자료 사용 원칙

### 내용 근거

1. 사용자의 현재 확정사항
2. 현재 사건의 공식 접수·이송·권익위 자료
3. 신고 원문과 제출자료
4. 담당부서 공식 회신과 증빙
5. 사용자가 지정한 최신 기준 문안

### 구조·문체 기준

1. 사용자가 현재 사건에 적용할 확정 실무 샘플을 직접 지정한 경우 그 샘플
2. `SAMPLE_CATALOG.md`에서 현재 산출물에 지정한 active 샘플
3. 구조 예시는 구조만, 문안 예시는 문체·문장 연결까지 참고

샘플은 사실·법령·소관의 근거가 아니다. 사건번호, 날짜, 부서, 법령, 처분상태와 연락처는 원자료에서 확인되지 않으면 `[확인 필요]`로 둔다.

특히 국민권익위원회 조사결과 회신에서는 다음을 구분한다.

- `권익위 통보 공문`, `조사결과 회신 공문` → `acrc_result_official_letter_masked_example.md`
- `권익위 제출용 서식`, `조사결과 서식`, `빠른 HWPX` → `acrc_result_notice_flat_masked_example.md` 또는 조건이 맞는 경우 `acrc_result_notice_two_level_masked_example.md`

제출용 서식의 `## 필드명` 구조를 시행 공문의 번호체계로 사용하지 않는다.

## 6. 기본 검토

- 각 신고 주장을 `공익신고 검토 대상 / 일반 민원·감사 참고 / 타 기관·별도 절차 / 보완 필요 / 확인 필요`로 구분한다.
- 확인 사실, 신고 주장, 담당부서 의견, 기관의 정리, 추가 확인을 혼합하지 않는다.
- 조치상태는 `예정 / 진행 / 완료`를 구분한다.
- 신고자 직접 식별정보뿐 아니라 신고자임을 미루어 알 수 있는 관계·경위·제보 경로를 최소화한다.
- 신고자 통지용, 국민권익위원회 시행 공문, 권익위 제출용 조사결과 서식, 불특정 다수 공개용 문안의 공개범위와 역할을 구분한다.
- 법적 효과·권한·이의신청 안내가 결론에 영향을 주면 현재 및 사안 당시 공식 근거의 확인 상태를 표시한다.

## 7. 답변 형식

1. `현재 업무 및 자료 신뢰도`
2. `사용한 정본과 비식별 샘플`
3. `쟁점별 분류·대조`
4. `핵심 판단과 확인 필요`
5. `해당 단계의 완성형 문안 또는 검토표`
6. `결재·발송 전 확인사항`

문안이 대외·결재용이면 `document-validation-pipeline`의 Chat 내용검증을 마무리 단계에 적용한다.

## 8. 시작 문구

```text
@GitHub m1의 CHATGPT_ENTRYPOINT.md에서 공익신고 경로를 적용해줘.
공익신고 SAMPLE_CATALOG.md와 현재 업무의 비식별 샘플을 실제로 읽은 뒤,
첨부한 현재 사건 원자료만으로 업무를 판별하고 검토 또는 초안을 작성해줘.
권익위 회신이면 시행 공문과 제출용 서식/HWPX를 먼저 구분해줘.
읽지 못한 파일은 읽었다고 가정하지 말고 먼저 알려줘.
```
