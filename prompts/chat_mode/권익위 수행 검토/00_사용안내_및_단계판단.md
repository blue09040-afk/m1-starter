# 고충민원 Chat 모드 프롬프트 사용 안내

## 1. 목적

이 폴더의 프롬프트는 자료가 많지 않아 Work 모드의 폴더 탐색·파일 작성·정리까지 필요하지 않을 때 사용한다. Chat 모드에서 현재 사건의 첨부파일과 사용자가 입력한 사항만을 기준으로 다음 업무를 수행하도록 설계했다.

1. 현재 처리단계와 자료의 신뢰도를 확인한다.
2. 사실·민원 주장·담당부서 의견·권익위 처리결과를 구분해 검토한다.
3. 결론이나 수신처를 바꿀 수 있는 사항만 먼저 질문한다.
4. 검토 결과와 복사 가능한 공문 초안을 대화창에 작성한다.
5. 결재·발송 전에 사람이 확인할 항목을 남긴다.

Chat 모드에서는 사건 폴더의 `AGENTS.override.md`, `PROJECT_AUTOMATION_GUIDE.md`, 샘플 HWPX 또는 이전 사건 파일을 자동으로 읽는다고 가정하지 않는다. 필요한 사건 원문과 현재 기준 문안은 같은 대화에 직접 첨부하거나 붙여넣어야 한다. 다만 `@GitHub m1-starter`을 사용하는 경우에는 재사용 구조를 위해 `skills/acrc-grievance-complaint-workflow/templates/SAMPLE_CATALOG.md`와 선택한 단계의 비식별 Markdown 샘플을 실제로 읽는다.

## 2. Chat 모드와 Work 모드 선택

### Chat 모드가 적합한 경우

- 현재 단계와 요청 업무가 비교적 분명하다.
- 검토할 문서가 소수이고 본문을 대화에서 안정적으로 읽을 수 있다.
- 필요한 결과가 검토의견과 복사 가능한 공문 문안이다.
- 실제 폴더 정리, 다수 파일의 상호 대조, HWPX 생성·수정이 필요하지 않다.

### Work 모드가 더 적합한 경우

- 자료가 여러 폴더에 흩어져 있거나 문서 수가 많다.
- 스캔 PDF, 손상 파일, 복잡한 표 등으로 별도 추출·OCR 검증이 필요하다.
- 실제 Markdown·HWPX 파일 작성, 샘플 서식 복제, 미리보기·레이아웃 검증이 필요하다.
- 사건자료 보존 이동, `HANDOFF_SUMMARY.md` 작성, 다음 사건 준비까지 해야 한다.
- 여러 단계의 자료가 섞여 있어 전체 사건 흐름을 장시간 교차검토해야 한다.

## 3. 단계 선택

| 단계 | 현재 자료 상태 | 사용할 프롬프트 |
|---|---|---|
| 1단계 | 권익위·도권위 등의 요청문과 민원 내용은 있으나 담당부서 회신은 없음 | `01_1단계_담당부서_의견자료요청.md` |
| 2단계 | 담당부서 검토의견·회신·증빙이 도착함 | `02_2단계_권익위_설명자료제출.md` |
| 3단계 | 권익위 등의 최종 처리결과가 도착했으나 **국민권익위원회의 법 제46조제2항 의견표명은 아님** | `03_3단계_처리결과_담당부서통보.md` |
| 4단계 | 국민권익위원회가 법 제46조제2항에 따른 **의견표명**을 의결하고 처리결과 통보 공문·의결서가 도착함 | `04_4단계_권익위_의견표명_담당부서통보.md` |

**4단계는 시간상 3단계 다음에 반드시 이어지는 순차 단계가 아니다. 최종 처리유형이 국민권익위원회의 법 제46조제2항 의견표명인 경우 일반 3단계 대신 적용하는 전용 분기이다.**

제47조에 따른 제도개선 의견표명은 현재 4단계 확정 샘플의 검증범위에 포함하지 않는다. 해당 사건은 3단계로 라우팅하되 법 제50조제1항의 30일 처리결과 통보와 시행령 제51조의 곤란 사유 통보 등 의견표명 후속절차를 반드시 별도로 확인한다.

여러 단계의 자료가 함께 있으면 가장 후속의 공식자료를 기준으로 하되, 최종 처리유형을 먼저 확인한다. 최종 처리유형이 제46조제2항 의견표명이면 4단계로 판별하고, 앞 단계의 사건번호·민원요지·담당부서 의견은 정합성 확인에만 사용한다.

## 4. 단계가 불분명할 때 먼저 붙여넣을 프롬프트

```text
첨부한 고충민원 자료를 기준으로 현재 업무를 1단계·2단계·3단계·4단계 중 어디로 라우팅할지 먼저 판별해 주세요.

- 1단계: 공식 요청문과 민원 내용은 있으나 담당부서 회신이 없는 상태
- 2단계: 담당부서 검토의견·회신 또는 증빙이 도착한 상태
- 3단계: 권익위 등의 최종 처리결과가 도착했으나 국민권익위원회의 법 제46조제2항 의견표명은 아닌 상태. 제47조 제도개선 의견표명도 현재는 이 단계에서 처리하되 법 제50조제1항·시행령 제51조의 후속절차를 별도로 확인함
- 4단계: 국민권익위원회가 법 제46조제2항에 따른 의견표명을 의결하고 처리결과 통보 공문과 의결서가 도착한 상태

4단계는 3단계 다음 순번이라는 뜻이 아니라 제46조제2항 의견표명 사건 전용 분기입니다. 최종 처리유형이 제46조제2항 의견표명으로 확인되면 3단계가 아니라 4단계로 분류하세요.

파일명만으로 판단하지 말고 문서 본문, 발신기관, 사건번호, 문서일자, 처리유형, 의결서 주문과 실제 회신·처리결과의 존재를 확인해 주세요. 여러 단계 자료가 함께 있으면 가장 후속 공식자료의 처리유형을 우선하되 앞 단계 자료와의 사건번호·민원요지 정합성을 확인해 주세요.

먼저 아래 순서로만 답해 주세요.
1. 판단한 현재 단계
2. 판단 근거가 된 첨부자료
3. 빠진 필수자료 또는 중대한 충돌
4. 다음에 사용할 단계별 프롬프트

합리적 가정으로 진행하면 단계나 결과가 달라질 수 있는 경우에만, 답변 전에 필요한 질문을 최대 3개까지 해 주세요. 아직 공문 초안은 작성하지 마세요.
```

## 5. 기본 사용 순서

1. 현재 단계에 필요한 원문을 같은 대화에 첨부한다.
2. `@GitHub m1-starter`에서는 샘플 카탈로그와 현재 단계의 비식별 Markdown 샘플을 실제로 열었는지 확인한다.
3. 해당 단계 파일의 `붙여넣기용 프롬프트` 전체를 복사해 입력한다.
4. 프롬프트 아래의 `사용자 추가 입력` 중 아는 항목만 채운다.
5. Chat이 먼저 질문하면 필요한 사항만 답한다.
6. 초안을 수정할 때는 새 대화를 열기보다 같은 대화에서 현재 초안을 기준으로 수정하도록 요청한다.
7. 사용자가 HWPX·ODT를 직접 수정한 뒤 다시 올렸다면, 이전 대화의 초안이 아니라 새로 첨부한 파일을 현재 기준본으로 지정한다.

## 6. 공통 주의사항

- 사건번호, 문서번호, 날짜, 금액, 수신처, 회신기한과 붙임 명칭은 추정해 만들지 않는다. 확인되지 않으면 `확인 필요`로 표시한다.
- 성명, 연락처, 상세 주소 등 개인정보는 판단과 문안에 필요한 최소 범위만 제공한다.
- 외부 OCR·변환 서비스 전송이 필요한 자료는 서비스와 대상을 확인한 뒤 별도로 승인한다.
- 사용자가 첨부한 현재 사건 샘플은 구조와 문체를 참고할 수 있다. `m1-starter`에서 `구조 예시`로 등재한 샘플은 구조만 참고하고, `문안 예시`로 등재한 경우에만 문체·문장 연결도 참고한다. 어느 경우든 샘플의 사건번호·사실·부서명·결재정보를 옮기지 않는다.
- 현재 단계·쟁점·회신 범위·수신처와 상충자료를 정리한 직후 `document-validation-pipeline`의 Chat 내용검증을 한 번 적용하고 문안을 작성한다. 작성 후에는 같은 검증결과와 문안의 일치만 확인하며, 사건 판단의 근거가 실질적으로 바뀐 경우에만 영향을 받는 부분을 다시 검증한다.
- 4단계에서 개별 의견표명 내용·처리결과의 공표 근거는 법 제53조, 고충민원 관련 위원회 운영상황의 연례 대통령·국회 보고 및 공표 근거는 법 제26조제1항으로 구분한다.
- 4단계의 적극행정 면책·기관평가 안내는 감사부서의 이행관리 목적상 사용할 수 있지만, 내부규정 조문번호·평가명·수용률 반영기준은 작성 시점의 현행 기준을 확인한다.
- Chat 답변은 내용 초안이다. 실제 HWPX의 결재선, 줄바꿈, 쪽 나눔, 붙임과 `끝.` 표시는 결재·발송 전에 별도로 확인한다.
