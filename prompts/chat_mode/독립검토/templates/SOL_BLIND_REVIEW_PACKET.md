# SOL_BLIND_REVIEW_PACKET

> 용도: Codex 또는 사용자가 일반 ChatGPT Sol High에 **1차 블라인드 독립검토용 사건정보**를 전달할 때 사용한다.
>
> 이 패킷은 사건 원자료를 대체하는 판단문이 아니라, 원자료와 함께 보는 **중립적 사건 인덱스**다. 패킷과 원자료가 충돌하면 원자료를 우선한다.

## 0. 블라인드 보호 규칙

이 패킷에는 다음 내용을 넣지 않는다.

- Codex의 잠정결론 또는 최종결론
- Codex가 선호하는 해결방향·권고안
- Codex 회신문·검토의견 초안
- Codex 검증보고서의 합격·불합격 판단
- 어떤 쟁점·자료가 더 중요하다는 Codex의 우선순위 평가
- `위법`, `적법`, `수용`, `기각`, `타당`, `부당` 등 결론을 미리 암시하는 요약
- Sol이 어떤 결론을 내려야 하는지 유도하는 문구

위 내용이 이미 현재 대화에 노출되었다면 완전한 블라인드 검토가 불가능하므로 `준블라인드`임을 표시한다.

### 법령자료 제공 모드

사건 성격에 따라 아래 중 하나를 선택한다.

- `엄격 블라인드`: 적용 법령 식별 자체가 핵심 쟁점이거나 법령 선택 편향을 최소화해야 할 때 사용한다. Codex가 선별한 법령 목록을 1차 패킷에 넣지 않고 Sol이 원자료에서 적용 법령을 독립적으로 식별·확인한다.
- `중립 목록 제공`: 자료가 많거나 법령 원문 재수집 비용을 줄일 필요가 있을 때 사용한다. 현재 확보된 법령·공식 자료 목록을 결론 없이 제공하되, 목록 밖의 법령·예외·경과규정 가능성을 열어 둔다.

선택한 모드: `엄격 블라인드 / 중립 목록 제공`

## 1. 사건 식별

- 사건 표시명:
- 검토 목적:
- 사용자 요청 범위:
- 기준일 또는 중요한 행위일:
- 현재 처리단계:
- 개인정보·비공개 정보 처리상 주의점:

※ 사건번호·성명·연락처·상세주소 등 식별정보는 검토에 꼭 필요한 경우가 아니면 최소화한다.

## 2. 제공 원자료 전체 목록

가능한 범위에서 검토 대상 자료의 **전체 목록**을 먼저 제시한다. 길이·형식 문제로 실제 첨부하지 못한 자료도 목록에서는 누락하지 않는다.

| ID | 자료명 | 작성·발신 주체 | 작성일/기준일 | 제공 형태 | 원문 제공 여부 |
|---|---|---|---|---|---|
| R1 |  |  |  | 원본/OCR/추출/요약 | 예/아니오 |

- 현재 확보되지 않은 것으로 알려진 자료:
- 판독 품질 문제가 있는 자료:
- OCR·추출본인 경우 원본 재확인이 필요한 항목:

※ 특정 자료를 `핵심`, `결정적`, `신뢰도 높음`이라고 미리 평가하지 않는다. 중요도와 증거가치는 Sol이 독립적으로 판단한다.

## 3. 민원인·신고자의 요청 또는 문제제기

원문의 의미를 바꾸지 않는 범위에서 중립적으로 정리한다.

- 요구 1:
  - 원자료 위치:
- 요구 2:
  - 원자료 위치:

민원인의 법적 평가나 단정은 `주장`으로 구분하고 객관적 사실처럼 옮기지 않는다.

## 4. 직접 확인되는 사실 후보

현재 자료에서 직접 읽히는 내용을 적되, 법적 의미나 최종 사실인정까지 미리 확정하지 않는다.

| 사실 ID | 내용 | 근거 원자료 | 원문 위치 | 원문 확인 상태 |
|---|---|---|---|---|
| F1 |  |  |  | 원본 확인/추출본만 확인/재확인 필요 |

- 해석이나 평가가 필요한 사항은 사실표에 섞지 않는다.
- 자료끼리 충돌하면 어느 한쪽을 선택하지 말고 `자료 간 상충·불일치` 절에 적는다.

## 5. 당사자·담당부서·기관의 진술 또는 의견

사실과 분리하여 출처별로 적는다.

| 의견 ID | 주체 | 내용 | 근거 원자료 | 원문 위치 |
|---|---|---|---|---|
| O1 |  |  |  |  |

※ 담당부서 의견을 기관의 확정적 법률판단으로 승격하지 않는다.

## 6. 공식 처분·조치·진행상태

| 조치 ID | 내용 | 표시된 상태 | 근거 원자료 | 기준일 |
|---|---|---|---|---|
| A1 |  | 예정/진행/완료/확인 필요 |  |  |

조치의 존재와 그 조치의 적법성·타당성 판단을 분리한다.

## 7. 자료 간 상충·불일치

결론을 붙이지 말고 무엇이 서로 다른지만 적는다.

| 충돌 ID | 자료 A | 자료 B | 서로 다른 내용 | 원문 위치 |
|---|---|---|---|---|
| C1 |  |  |  |  |

어느 자료가 더 신뢰할 만한지는 이 패킷 작성자가 정하지 않는다.

## 8. 관련 가능성이 있어 수집된 법령·공식 기준 자료

`중립 목록 제공` 모드일 때만 작성한다. `엄격 블라인드` 모드라면 이 절을 비우고 Sol이 적용 법령 자체를 독립적으로 식별하도록 한다.

이 절은 **적용 법령을 확정하는 절이 아니다.** 현재까지 수집된 공식 자료의 목록만 제시한다.

| L-ID | 법령·기준명 | 조문·항목 | 시행일/기준일 | 출처 | 원문 확인 상태 |
|---|---|---|---|---|---|
| L1 |  |  |  |  |  |

- 과거 사안이면 당시 시행본 확보 여부:
- 최신 시행본 확보 여부:
- 원문 미확인 또는 접속 실패 자료:

※ 목록에 있다는 이유만으로 적용 법령이라고 보지 않는다. 반대로 목록에 없다는 이유만으로 다른 적용 법령·예외·경과규정을 배제하지 않는다. Sol은 필요한 경우 적용 법령 자체를 독립적으로 재탐색·확인한다.

## 9. 아직 확인되지 않은 사항

패킷 작성자의 중요도 평가를 붙이지 않고, 현재 비어 있는 사실·자료만 적는다.

| U-ID | 미확인 사항 | 현재 확인 가능한 자료/기관 | 관련 원자료 위치 |
|---|---|---|---|
| U1 |  |  |  |

어떤 미확인 사항이 결론을 실제로 바꿀지는 Sol이 독립검토에서 판단한다.

## 10. 사용자 지정 검토질문

사용자가 직접 요청한 질문이나 검토 범위만 적는다. Codex가 만든 잠정 쟁점구조를 독립검토에 주입하지 않는다.

- Q1:
- Q2:
- Q3:

사용자가 특정 질문을 지정하지 않았다면 `사건 원자료만으로 핵심 쟁점을 독립적으로 설정할 것`이라고 적는다.

## 11. 실제 함께 제공하는 원문·발췌

패킷 요약만으로 판단하지 않도록 실제 첨부하거나 붙여넣는 원문을 표시한다.

| 제공 ID | 자료 ID | 제공 범위 | 생략된 범위 | 제공 이유 |
|---|---|---|---|---|
| P1 | R1 | 전체/쪽·문단 범위 | 없음/있음 | 사용자 요청 범위/길이 제한/판독 가능 범위 등 중립적 사유 |

- `제공 이유`에는 `결론에 결정적`, `가장 중요한 증거`처럼 판단을 유도하는 평가를 넣지 않는다.
- 일부만 제공했다면 생략 사실과 범위를 표시한다.
- 가능한 경우 민원·신고 원문, 담당부서 회신·처분문, 행위시점이나 권한을 확인할 자료를 함께 제공한다.
- 법령 원문은 `법령자료 제공 모드`에 따른다.

## 12. 패킷 작성자 자체검증

- [ ] Codex의 잠정결론·권고안·초안이 섞이지 않았는가
- [ ] Codex가 정한 쟁점·자료 중요도 순위를 주입하지 않았는가
- [ ] 사실 후보와 당사자·담당부서 의견이 분리되었는가
- [ ] 선택한 법령자료 제공 모드가 사건의 독립성 요구에 맞는가
- [ ] `중립 목록 제공` 모드에서도 적용 법령을 미리 확정하거나 목록으로 범위를 제한하지 않았는가
- [ ] 조치의 존재와 적법성 판단을 혼동하지 않았는가
- [ ] 날짜·수치·기관명·원문 위치를 임의로 만들지 않았는가
- [ ] 미확인 사항에 결론 영향도를 미리 매기지 않았는가
- [ ] 개인정보를 필요 이상으로 넣지 않았는가
- [ ] 전체 자료 목록과 실제 제공 범위의 차이를 표시했는가
- [ ] 패킷에 없는 원자료를 있는 것처럼 전제하지 않았는가

## 13. Sol High에 붙일 호출문

```text
[독립검토-1]
이 패킷은 1차 블라인드 독립검토를 위한 중립적 사건 인덱스입니다.

m1의 CHATGPT_ENTRYPOINT.md와
prompts/chat_mode/독립검토/00_독립검토_운용원칙.md,
prompts/chat_mode/독립검토/01_민원_블라인드_독립검토.md를 적용해 주세요.

- Codex 결과·잠정결론·회신문 초안을 찾아보거나 요구하지 마세요.
- 패킷 요약보다 첨부 원자료를 우선하세요.
- `엄격 블라인드` 모드이면 패킷 밖에서 적용 법령을 독립적으로 식별·확인하세요.
- `중립 목록 제공` 모드이면 제공된 법령 목록을 완전한 범위라고 전제하지 마세요.
- 패킷이 이미 결론·중요도·쟁점 우선순위를 암시한다고 판단되면 그 편향 가능성을 먼저 표시하세요.
- 핵심 쟁점을 독립적으로 설정하고, 사실·법령·권한·시점·반론을 검토하세요.
- 마지막에는 2차 비교용 `비교기준 스냅샷`을 작성하세요.
```
