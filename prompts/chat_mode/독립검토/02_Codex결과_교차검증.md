# Codex 결과 교차검증 프롬프트

## 1. 목적

이 프롬프트는 `01_민원_블라인드_독립검토.md`에서 형성한 ChatGPT Sol High의 **고정된 `비교기준 스냅샷`**과 이후 제공된 Codex 검토 결과를 쟁점별로 비교하여, 단순 문구 차이가 아니라 **결론을 바꿀 수 있는 사실·법령·권한·시점·증거 수준의 차이**를 찾기 위한 것이다.

교차검증의 목적은 Codex와 Sol 중 한쪽을 기계적으로 우선하거나 두 결론을 절충하는 것이 아니다. 서로 다른 판단 경로가 왜 갈라졌는지 추적하고, 더 강한 근거를 가진 판단을 식별하는 데 있다.

## 2. 적용 조건

다음 자료가 있을 때 적용한다.

- 앞선 Sol High 독립검토의 `비교기준 스냅샷`
- Codex가 작성한 검토결과, 초안, 검증보고서 또는 핵심 판단
- 가능하면 두 결과의 근거가 된 사건 원자료

앞선 독립검토 또는 스냅샷이 없는 경우에는 먼저 `01_민원_블라인드_독립검토.md`를 적용하는 것이 원칙이다. 다만 사용자가 즉시 비교를 요청하면 현재 자료만으로 비교하되 `사전 독립판단 없음`을 명시하고, 사후에 1차 판단을 복원해 블라인드 검토였던 것처럼 표현하지 않는다.

새 대화에서 2단계를 수행하는 경우에는 이전 대화의 `비교기준 스냅샷`을 직접 첨부·붙여넣기 한다. 없는 내용을 기억했다고 가정하지 않는다.

## 3. 참조 기준

- 독립성 원칙은 `00_독립검토_운용원칙.md`를 따른다.
- 공통 행정 판단 기준은 `guides/BASE_INSTRUCTIONS.md`를 참고한다.
- 공익신고 핵심 쟁점이면 `skills/public-interest-report-review/SKILL.md`를 추가 참조한다.
- 문안 품질보다 **판단 차이와 근거 차이**를 우선한다.

## 4. 비교 원칙

1. `비교기준 스냅샷`의 Sol 1차 판단을 Codex 결과에 맞춰 사후적으로 다시 쓰지 않는다.
2. 스냅샷의 `S1`, `S2` 같은 쟁점번호를 가능한 한 유지하여 비교한다.
3. Codex와 Sol의 표현이 달라도 실질 판단이 같으면 `일치`로 본다.
4. 동일 결론이라도 근거가 다르거나 한쪽이 핵심 예외를 누락하면 `조건부 일치`로 본다.
5. 결론이 다르면 다음 원인을 우선 분해한다.
   - 사실관계 인식 차이
   - 민원인 주장과 객관적 사실의 구분 차이
   - 적용 법령 또는 조문 차이
   - 시행일·경과규정·사안 당시 법령 차이
   - 처분권한·관할·소관 판단 차이
   - 예외 규정 또는 별도 불복절차 누락
   - 증거 신뢰도·범위 해석 차이
   - 조치상태(예정·진행·완료) 인식 차이
6. 한쪽 결과가 원자료에 없는 사실을 전제로 하면 그 부분을 명확히 지적한다.
7. 법령·정책·관할의 차이가 결론을 좌우하면 공식 원문을 다시 확인한다. 확인하지 못하면 승자를 억지로 정하지 않는다.
8. 결론 차이를 문구상 절충으로 덮지 않는다.
9. Sol 자신이 놓친 부분이 확인되면 `Sol 누락/오류`로 명확히 인정하고 스냅샷 자체는 고치지 않는다.
10. Codex가 더 타당하면 `Codex 우세`, Sol이 더 타당하면 `Sol 우세`, 추가 확인 없이는 판단하기 어렵다면 `판정 보류`로 표시한다.

## 5. 차이 분류

각 쟁점은 다음 중 하나로 분류한다.

- `일치`: 실질 결론과 핵심 근거가 동일
- `조건부 일치`: 결론은 같지만 전제·예외·근거 보완이 필요
- `경미한 차이`: 결론에 영향 없는 표현·정리 수준의 차이
- `중대 충돌`: 사실·법령·권한·시점 차이로 결론 또는 조치가 달라짐
- `Codex 누락`: Sol 검토에서 확인한 중요 쟁점이 Codex 결과에 없음
- `Sol 누락`: Codex가 확인한 중요 쟁점을 Sol 1차 검토가 놓침
- `판정 보류`: 결정적 자료 또는 공식 근거가 부족함

## 6. 기본 출력 형식

### 1. 교차검증 결론

- 전체적으로 두 결과가 얼마나 일치하는지 3~6줄로 정리한다.
- 중대 충돌이 있으면 가장 먼저 밝힌다.
- 단순 문체 차이는 핵심 결론에서 제외한다.

### 2. 쟁점별 대조표

| 스냅샷 번호 | 쟁점 | Codex 판단 | Sol 1차 판단 | 분류 | 근거 우세 | 필요한 조치 |
|---|---|---|---|---|---|---|
| S1 |  |  |  |  |  |  |

`근거 우세`는 `Codex 우세 / Sol 우세 / 동등 / 판정 보류` 중 하나로 표시한다.

Codex에서만 새로 발견된 중요 쟁점은 `C1`, `C2`처럼 별도 번호를 붙여 `Sol 누락`으로 추가한다.

### 3. 중대 차이 상세검증

`중대 충돌`, `Codex 누락`, `Sol 누락`, `판정 보류` 항목만 상세 검토한다.

각 항목은 다음 순서로 정리한다.

- **충돌 또는 누락 지점**
- **Codex가 사용한 전제·근거**
- **Sol 스냅샷의 전제·근거**
- **원자료 대조 결과**
- **법령·권한·시점 확인 결과**
- **어느 판단이 더 강한지**
- **최종 반영 권고**

### 4. 서로가 놓친 사항

#### Codex가 놓친 사항

실제로 확인된 항목만 적는다. 억지로 차이를 만들지 않는다.

#### Sol이 놓친 사항

1차 독립검토에서 누락했으나 Codex 결과와 원자료 재대조를 통해 확인된 중요사항을 적는다.

둘 다 없으면 `중요 누락 없음`으로 표시한다.

### 5. 최종 판단안

교차검증 후 다음 중 하나로 정리한다.

- `Codex 판단 유지 권고`
- `Sol 독립판단 반영 권고`
- `양측 결론은 같고 근거만 보완`
- `일부 쟁점만 수정 필요`
- `추가 확인 전 결론 확정 곤란`

이때 왜 그렇게 판단하는지 핵심 근거를 짧게 붙인다.

### 6. 추가 확인 필요사항

교차검증 후에도 결론을 바꿀 수 있는 미확인 사항만 최대 3개 남긴다.

### 7. 스냅샷 보존 확인

마지막에 다음을 짧게 표시한다.

- `Sol 1차 스냅샷 변경 여부: 변경 없음`
- `Sol 누락/오류 확인: 있음 / 없음`
- `Codex 누락/오류 확인: 있음 / 없음`

`Sol 누락/오류`가 있어도 1차 스냅샷 원문을 고치지 않고 2단계 판정에만 기록한다.

## 7. 검토 강도

사용자가 별도 지시하지 않으면 다음 기준으로 검토한다.

- 단순 표현 차이: 빠르게 분류
- 사실관계 차이: 원자료 재대조
- 법령·권한·시점 차이: 공식 근거 재확인
- 결론을 뒤집는 차이: 가장 높은 우선순위로 상세검증

## 8. 금지사항

- Codex와 Sol이 다르다는 이유만으로 둘 중 하나를 자동 채택하지 않는다.
- 양측 결론을 평균내거나 모호한 절충문으로 덮지 않는다.
- Sol의 최초 스냅샷을 사후적으로 수정해 마치 처음부터 Codex와 같았던 것처럼 표현하지 않는다.
- Codex 결과에 적힌 사실을 원자료 확인 없이 객관적 사실로 승격하지 않는다.
- 실제 확인하지 않은 법령·판례·행정해석을 확인했다고 말하지 않는다.
- 사전 독립판단이 없는데 사후 비교 결과를 `블라인드 독립검토`로 표현하지 않는다.

## 9. 붙여넣기용 호출문

```text
[독립검토-2]
앞서 만든 `비교기준 스냅샷`을 원문 그대로 비교 기준으로 유지한 상태에서, 지금 제공하는 Codex 검토 결과와 교차검증해 주세요.

- 스냅샷의 S1, S2 번호를 유지해 비교하세요.
- 표현 차이보다 사실·법령·권한·시점·증거 수준의 차이를 우선하세요.
- 쟁점별로 `일치 / 조건부 일치 / 경미한 차이 / 중대 충돌 / Codex 누락 / Sol 누락 / 판정 보류`를 구분하세요.
- 결론이 다르면 절충하지 말고 원자료와 공식 근거를 다시 대조하여 어느 판단이 더 강한지 설명하세요.
- 네 1차 검토가 틀렸거나 놓친 부분도 숨기지 말고 `Sol 누락/오류`로 기록하되 스냅샷 자체는 수정하지 마세요.
- 결론을 실제로 바꿀 수 있는 미확인 사항만 최대 3개 남기세요.
```
