# 인수인계 요약 작성 프롬프트

현재 세션의 상위 지침과 `AGENTS.md`의 라우팅·신뢰 경계를 우선하세요. 행정 판단을 새로 요약하거나 확인해야 할 때만 `guides/BASE_INSTRUCTIONS.md`의 관련 절을 참고하세요.

공익신고 사건이면 `public-interest-report-review` 스킬을 함께 적용하세요.

다른 대화방을 열어 처음부터 검토하더라도 이어갈 수 있도록 `HANDOFF_SUMMARY.md`를 작성하거나 업데이트하세요.

`HANDOFF_SUMMARY.md`는 과거 작업을 다시 장문으로 요약하는 문서가 아니라, **다음 작업자가 최소한의 컨텍스트만 읽고 현재 상태에서 바로 이어가기 위한 압축 인수인계 파일**입니다. 세부 사실과 근거가 기존 산출물에 있으면 이를 반복 복사하지 말고 필요한 파일을 가리키세요.

## 기본 구성

### 1. 현재 목적과 상태

- 작성·갱신 기준 시점과 현재 단계를 적습니다.
- 지금 이 사건에서 무엇을 마무리하려는지 1~3개 항목으로 적습니다.
- 가장 최근에 완료한 작업과 그 이후 새 산출물이 생겼는지 적습니다.

### 2. 확정된 사실·결정

- 다음 작업의 방향을 바꾸는 핵심 사실, 확정 판단, 사용자 확정 기준만 적습니다.
- `확정`, `잠정`, `확인 필요`, `검토 제외`, `타 기관 소관` 등 상태가 중요하면 함께 표시합니다.
- 신고자 주장, 부서 조사결과, 법령 검토 내용을 장문으로 다시 옮기지 않습니다. 다음 판단에 직접 필요한 경우에만 1~2줄로 요약하고 근거 파일을 적습니다.

### 3. 미해결 쟁점·확인 필요

- 아직 결론이 나지 않은 쟁점과 그 이유를 적습니다.
- 추가로 확인할 법령, 원자료, 부서 의견, 개인정보·비공개 범위를 구분합니다.

### 4. 다음 작업

- 다음 세션에서 실제로 수행할 작업을 우선순위 순으로 적습니다.
- 이미 끝난 검토를 반복하지 않도록 완료된 단계와 재검토가 필요한 단계를 구분합니다.

### 5. 다음 세션에서 반드시 읽을 파일

- 다음 작업에 직접 필요한 최소 파일만 순서대로 적습니다.
- 작성 시 실제로 존재하는 파일인지 확인하고, 가능하면 사건 폴더 기준 상대경로로 적습니다.
- 각 파일 옆에 `왜 읽어야 하는지`를 한 줄로 표시합니다.
- HANDOFF 작성 이후 더 최신 산출물이 생겼다면 그 최신 원문을 우선하고, 오래된 파일을 현재 정본처럼 가리키지 않습니다.
- 그 밖의 중간 산출물은 현재 쟁점에서 필요할 때만 확인하도록 적습니다.

예시:

```md
## 다음 세션에서 반드시 읽을 파일
1. `900_종합검토의견_최종.md` — 현재 판단과 사용자 확정 기준
2. `source_log.md` — 법령·공식자료 확인 상태
3. `부서회신_요약.md` — 아직 해결되지 않은 쟁점의 부서 입장

그 밖의 중간 산출물은 현재 쟁점에 필요할 때만 확인한다.
```

### 6. 안전·공유 경계와 마무리 메모

- 다음 작업에 영향을 주는 개인정보·비공개·외부전송 제한이 있을 때만 적습니다.
- 사건 폴더, 산출물 파일명, `다음에 읽을 파일`, 미해결 사건 상태는 **HANDOFF에만** 둡니다. 이를 장기 memory의 `history/`, `knowledge/`, `preferences/`, `workflows/`에 사건 재개용 색인으로 복제하지 않습니다.
- 공문 수정 과정에서 재사용 가능한 사용자 선호·업무유형별 패턴이 실제로 확인됐고 장기 memory 저장이 필요한 경우에만 `skills/document-revision-memory/SKILL.md`와 해당 저장소 계약을 별도로 적용합니다. 이때도 사건 고유 사실·실제 파일명·폴더명은 memory에 넣지 않습니다.
- 기존 `LLM_Wiki/`는 새 기록 정본이 아니라 legacy 이전 원본입니다. 인수인계 과정에서 갱신하지 않으며, 이전 작업이 필요할 때만 `prompts/migrate_llm_wiki_to_memory.md`를 적용합니다.

## 작성 원칙

- 기존 검토 결과와 산출물을 우선 활용합니다.
- 다음 작업에 필요하지 않은 과거 경과, 프롬프트 개선 논의, 지침 개선 논의, 모델 성능 평가, 다른 AI 서비스 비교, 사건과 무관한 작업 메모는 넣지 않습니다.
- 사건 원문, 신고자 주장 전문, 부서 회신 전문, 법령 전문, 기존 검토서 전문을 HANDOFF에 복제하지 않습니다.
- 요약 때문에 의미가 달라질 위험이 있는 결정적 사실이나 법적 근거는 HANDOFF 문구만 믿지 말고 `반드시 읽을 파일`에 원문 또는 정본을 지정합니다.
- HANDOFF와 실제 폴더가 충돌하면 실제 존재하는 최신 원자료·최종 산출물·현재 지침을 우선합니다.
- 다음 작업자가 바로 이어서 일할 수 있는 최소 정보가 확보되면 더 늘리지 않습니다.
- HANDOFF 작성·갱신 적용 조건은 `guides/BASE_INSTRUCTIONS.md` 45-3을 따릅니다. 이 프롬프트를 사용한 인수인계 요청에서는 필요한 HANDOFF만 작성하며, legacy Wiki나 장기 memory 기록을 자동으로 덧붙이지 않습니다.
- 장기 memory 반영이 실제로 필요한 경우에만 `prompts/update_llm_wiki.md`(호환 파일명) 또는 `document-revision-memory`를 적용하고, 실제 저장 여부와 미저장 후보를 구분해 보고합니다. 필수 사건 종료·보존 절차는 해당 사건 스킬을 따릅니다.
