# Grok 작업 하네스

> 적용 범위: `GROK_ENTRYPOINT.md` 적용 게이트를 통과한 뒤, 다문서·법령 수집·목록 대사가 실익이 있을 때만 적용한다.
>
> 이 문서는 `guides/harness_structure_guide_v1_3.md`와 `guides/chatgpt_sol_external_review_harness.md`를 대체하지 않는다. Codex 내부 위임·ChatGPT 외부 통로의 정본은 그곳에 남는다.

## 1. 목적

Grok 일반 Chat에는 Luna·Terra·Sol 모델분할이 없다. 하네스는 서브에이전트를 만드는 절차가 아니라, **한 모델이 GitHub·검색 도구를 쓸 때의 범위·오염·누락 방지**만 정한다.

단일 문안 수정, 추출본 1~2개, 짧은 확인에는 이 파일을 열지 않는다.

## 2. Codex·ChatGPT 하네스와의 관계

| 경로 | 역할 | Grok과의 관계 |
|---|---|---|
| Codex 내부 하네스 | 모델분할·병렬 위임 | 호출하지 않음 |
| ChatGPT Sol 외부 하네스 | 기본 외부 독립검토 | 기본 유지. Grok은 폴백·명시 요청만 |
| 이 문서 | Grok Chat 도구 범위 | 시험 관찰. 자동 제안 금지 |

Codex는 ChatGPT가 가능한 동안 Grok 외부검토를 준비·권고하지 않는다. `제3자 검토`라는 표현만으로 이 문서를 열거나 Grok으로 전환하지 않는다.

## 3. 도구 레인

병렬 단위는 에이전트가 아니라 도구다. 같은 판단 지점을 여러 레인에 나눠 쓰지 않는다.

| 레인 | 하는 일 | 하지 않는 일 |
|---|---|---|
| GitHub 목록 | 지정 사건 트리, `extracted/` 목록, 누락 대사 | 1차에 `result/`·HANDOFF·CODEX/SOL 검토파일 본문 열기 |
| GitHub 원문 | 지정된 `extracted/*.md`, 마스킹본 | 다른 사건 폴더 탐색, 비식별 안 된 원문 추정, 안 읽히는 `source/` 바이너리를 읽은 것처럼 쓰기 |
| 웹·법령 | 공식 법령·시행일·권한 | 사건 식별정보를 검색어에 넣기 |
| 쓰기(제공 시) | 현재 세션에서 확인된 GitHub 쓰기 도구·권한으로 `result/GROK_REVIEW.md` 등 결과 파일 저장·갱신 | 쓰기 미확인 상태에서 저장 성공 가정, 우회 인증, `m1`에 사건 본문 누적, `extracted/` 직접 수정 |
| 세션 내 임시 작업(제공 시) | 비식별 텍스트 정리 | 사건 원문·개인정보 처리, 제공되지 않은 샌드박스 기능을 있다고 가정 |

GitHub 커넥터는 읽기 연결만 확인되었다고 해서 파일 쓰기까지 가능하다고 가정하지 않는다. 현재 세션에서 실제 쓰기 도구와 대상 저장소 권한을 확인한 경우에만 쓰기 레인을 사용한다. 쓰기 도구가 없거나 권한이 불명확하면 결과 전문을 대화에 반환한다. 같은 이름의 기존 결과 파일은 **최신 검토결과로 갱신하는 것을 기본값**으로 하며, 이전 버전은 Git 커밋 이력에서 복구할 수 있다. 1차 블라인드에서는 기존 결과의 본문을 읽지 않은 채 현재 결과로 갱신할 수 있다.

## 4. 분해 위험 게이트

문서 관계, 예외, 시점, 권한, 반대자료가 결론을 바꾸면 자료별로 결론을 내지 않는다. 목록·추출 열람·조문 위치 찾기만 나누고, 잠정결론은 한 경로에서 원문 위치를 다시 대조한다.

## 5. GitHub 목록 오염 방지

저장소 트리와 파일명 자체도 1차 블라인드에서는 기존 판단을 노출하는 오염 경로가 될 수 있다.

- 지정 사건 폴더의 트리를 볼 때는 `source/`, `extracted/` 존재 여부만 확인한다.
- `HANDOFF_SUMMARY.md`, `CODEX_REVIEW.md`, `SOL_EXTERNAL_REVIEW.md`, `result/` 하위 파일은 이름을 대장에 기록하되 본문은 읽지 않는다.
- 다른 사건 폴더, `working/`의 Codex 메모, 검증보고서를 1차 근거로 쓰지 않는다.
- 결과 파일에는 실제 읽은 파일과 읽지 않은 파일을 분리해 적는다.

## 6. 완전성 대사

다문서·고위험일 때만 지정 추출본에 대해 아래를 남긴다. 소규모·저위험에는 만들지 않는다.

```text
지정 추출본 수 = 읽음 + 제외(사유) + 미확인 + 판독 불가
```

판독 불가·형식 깨짐은 추정하지 않고 Codex 확인 항목으로 남긴다.

## 7. 결과 통합

Grok 결과는 관찰 데이터다. Codex·ChatGPT 결론을 자동 폐기하거나 Grok 결론을 상위 판단으로 올리지 않는다. 차이가 있으면 원자료·법령·권한·시점으로 대조한 뒤 `반영 / 미반영(사유) / 추가 확인 / 판단 보류`만 기록한다.

시험 중 공통 지침 후보가 생기면 사건 파일에 섞지 말고 사용자가 요청할 때 `improvements/`에만 남긴다.

## 8. 금지사항

- 이 경로에 Luna/Terra/Sol 또는 Grok Build 서브에이전트 구조를 이식하지 않는다.
- ChatGPT가 가능한데 Grok을 기본 외부검토로 올리지 않는다.
- 수행하지 않은 원본 판독, 로컬 실행, 법령 원문 확인을 수행했다고 쓰지 않는다.
- 1차 블라인드에서 기존 검토 결과를 찾아 읽지 않는다.
- 시험 결과를 근거로 공통 정본을 바로 고치지 않는다.
