# 고충민원 샘플과 비식별 예시 관리

공통 승격·비식별·GitHub 반영 기준은 `skills/guidance-repo-maintenance/references/deidentified_sample_publishing_standard.md`를 정본으로 한다. 이 문서는 권익위 고충민원에 필요한 단계별 추가 기준만 둔다.

## 역할 구분

- 실제 결재·발송 확정본: 사건정보가 남을 수 있는 비공유 참조본이며 GitHub·Chat 프로젝트·공유 패키지에 넣지 않는다.
- 비식별 Markdown 구조 예시: 문단·필드·필수·선택 항목과 붙임 구조를 설명하는 재사용 정본이다.
- 비식별 Markdown 문안 예시: 완전히 가상화한 사실관계로 문체와 문장 연결을 설명하며, 별도 검증 뒤 카탈로그에 등재한다.
- HWPX 작성: 현재 사건의 검토 완료 Markdown과 사용자가 제공한 적합한 양식을 기준으로 `hwp-hwpx-processing`을 적용한다.

## 승격 절차

1. 사용자가 결재·발송 확정을 명시한 문서만 구조 검토 후보로 삼는다.
2. 원본은 사건 폴더의 비공유 참조로 보존하고 직접 자동작성·공유에 사용하지 않는다.
3. 새 Markdown 예시에는 실제 사건번호, 민원명·사실, 주소·지번, 판결·처분정보, 부서·직원명, 문서번호·날짜, 기한, 연락처, 결재·시행정보를 복사하지 않는다.
4. 필드명과 문단 순서, 필수·선택 항목, 붙임 구조만 중립 문구와 `20XX`, `0000`, `ㅇㅇ` 값으로 옮긴다.
5. 기존 예시를 바꾸면 `templates/SAMPLE_CATALOG.md`의 상태·채택일을 갱신하고, 변경한 구조와 검증 근거를 기본지침 채택 이력에 남긴다.

현재 기본 예시는 1·2·3단계 Markdown 구조만 제공하며 `templates/SAMPLE_CATALOG.md`에서 선택한다. 실제 HWPX와 비공유 참조본이 없더라도 Chat에서 읽을 수 있도록 설계한 것이며, 서식·레이아웃 무손실을 보증하지 않는다.
