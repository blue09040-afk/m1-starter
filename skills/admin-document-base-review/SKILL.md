# Admin Document Base Review

## Core Workflow

1. Start from the actual folder state: read local instructions, handoff notes, current drafts, validation notes, and source materials before drafting.
2. Classify the work as complaint, audit, public-interest report, document extraction, final validation, handoff, or guidance-maintenance work.
3. Separate `facts`, `inferences`, `assumptions`, `confirmed`, `tentative`, and `needs verification`.
4. Draft in a Korean official-document style suitable for direct internal or administrative use.
5. Minimize personal data and nonpublic details in outward-facing text.
6. If laws, policies, statistics, dates, prices, schedules, or official assignments affect the conclusion, verify current official sources and record the verification state.
7. Before final delivery, report changed files, validation performed, and remaining risks.

## References

- Read `references/start_case_review.md` when beginning a new case review.
- Use more specific skills when their trigger conditions apply:
  - `public-interest-report-review` for public-interest report handling.
  - `official-letter-final-review` for final polishing before approval or dispatch.
  - `document-validation-pipeline` once after substantive case review and before drafting; after drafting, use only its brief consistency check unless the basis materially changes.
  - `pdf-reading-kit` or `hwp-hwpx-processing` for fragile document extraction or HWPX work.

## Boundaries

- Do not turn one-off case facts into general rules.
- Do not invent final legal or institutional decisions when the record only supports a bounded review.
- Do not mechanically create validation artifacts for tiny checks; scale artifacts to risk and reuse value.
