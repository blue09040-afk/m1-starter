# 지속 개선 루프 지침

## 1. 목적

이 지침은 사건 처리, 문서 검토, 도구 실행 과정에서 얻은 반복 가능한 교훈을 공통 지침·프롬프트·실행 키트로 안전하게 반영하기 위한 기준이다.

기본 방향은 다음과 같다.

- 경험을 그대로 누적하지 않고, 재사용 가능한 교훈만 추출한다.
- 사건 고유 사실, 개인정보, 내부 문서번호, 담당자 정보는 공통 지침으로 승격하지 않는다.
- 자동 반영이 아니라 후보화, 검토, 사용자 승인 또는 명시 요청, 반영, 재검증 순서로 운영한다.
- 실패한 도구와 대체 절차는 같은 실패를 줄일 수 있으면 공통 지침 후보로 남긴다.

## 2. 적용 시점

다음 경우에 적용한다.

- 사용자가 작업 마무리, 인수인계, 최종 검증, 지침 업그레이드, 지속 개선을 요청한 경우
- 복합 사건을 끝낸 뒤 반복 가능한 절차나 실패 대응이 새로 확인된 경우
- 같은 유형의 오류, 누락, 도구 실패가 반복된 경우
- 새 키트, 새 프롬프트, 새 검증 기준으로 분리할 만한 작업 흐름이 생긴 경우
- 기존 지침이 실제 업무와 맞지 않거나 오래된 것으로 확인된 경우

단순 문안 수정, 짧은 질의응답, 일회성 자료 정리에서는 적용하지 않는다.

## 3. 개선 루프

### 3.1 수집

작업 종료 또는 인수인계 단계에서 다음을 확인한다.

- 이번 작업에서 시간이 많이 든 반복 절차
- 같은 유형의 실수나 누락이 발생한 지점
- 도구 실패와 효과가 있었던 대체 경로
- 사용자가 새로 정한 문안 기준 또는 검토 기준
- 다음 사건에서 먼저 확인해야 할 자료 구조
- 기존 지침과 충돌하거나 보완이 필요한 부분

### 3.2 분류

수집한 항목은 다음 중 하나로 분류한다.

| 분류 | 처리 |
|---|---|
| 사건 고유 사실 | 사건 폴더 산출물 또는 `HANDOFF_SUMMARY.md`에만 남김 |
| 사용자 선호 | 반복 적용될 때만 공통 지침 또는 메모리 후보로 검토 |
| 반복 절차 | 프롬프트, 가이드, 키트 절차 후보로 등록 |
| 검증 기준 | `validation_pipeline.md` 또는 관련 체크리스트 후보로 등록 |
| 도구 실패·대체절차 | 해당 처리 가이드 또는 키트 `HANDOFF.md` 후보로 등록 |
| 공통 지침 후보 | `improvements/candidate_lessons.md`에 등록 후 반영 검토 |
| 폐기·수정 필요 지침 | `improvements/stale_review_log.md`에 등록 |

### 3.3 후보화

공통 지침에 바로 반영하지 않고 먼저 `improvements/candidate_lessons.md`에 다음 형식으로 남긴다.

```md
## YYYY-MM-DD 후보명

- 출처 작업:
- 반복 가능성:
- 적용 대상:
- 반영 후보 파일:
- 제외할 사건 고유 정보:
- 위험:
- 제안 문안:
- 상태: 후보
```

단, 사용자가 현재 턴에서 명시적으로 "반영해줘", "지침에 넣어줘"라고 요청한 경우에는 후보 등록과 실제 반영을 같은 턴에서 처리할 수 있다. 이 경우에도 사건 고유 정보와 개인정보 제거 여부를 먼저 점검한다.

### 3.4 반영

반영 위치는 다음 기준으로 정한다.

| 반영 위치 | 기준 |
|---|---|
| `AGENTS.md` | 모든 작업 시작 시 적용해야 하는 짧은 라우팅 규칙 |
| `README.md` | 사람이 폴더를 열었을 때 알아야 할 안내 |
| `guides/BASE_INSTRUCTIONS.md` | 모든 사건에 적용되는 공통 판단·작업 원칙 |
| 개별 `guides/*.md` | 특정 문서 형식, 검증, 법령, 부서 확인 등 분야별 기준 |
| `prompts/*.md` | 반복 작업을 시작하거나 마무리할 때 재사용할 입력문 |
| `tools/PDF_READING_KIT/`, `tools/HWPX_READING_KIT/` | 실행 도구와 직접 관련되는 절차 |
| `improvements/` | 아직 확정하지 않았거나 검증 중인 후보 |

### 3.5 기록

공통 지침에 반영한 뒤에는 `improvements/adoption_log.md`에 다음을 남긴다.

- 반영일
- 반영 파일
- 반영 내용
- 출처 작업 또는 계기
- 검증 방법
- 남은 위험

### 3.6 재검증

반영된 지침은 다음 유사 작업에서 실제로 도움이 되었는지 확인한다.

- 작업 시작 시 과도하게 적용되어 방해되지 않았는가
- 검증 항목이 누락을 줄였는가
- 문안이 너무 일반적이거나 모호하지 않은가
- 보안·개인정보 위험을 늘리지 않았는가
- 오래된 도구 경로나 파일명을 가리키지 않는가

문제가 있으면 `improvements/stale_review_log.md`에 남기고 수정 또는 폐기를 검토한다.

### 3.7 정기 재검토와 폐기

`improvements/adoption_log.md`에 반영된 지침은 이후 유사 작업에서 계속 유효한지 점검한다. 원칙적으로 같은 유형의 작업을 3회 이상 수행했거나, 사용자 피드백으로 지침의 부작용이 확인된 경우 재검토한다.

다음 중 하나에 해당하면 `improvements/stale_review_log.md`에 등록한다.

- 지침이 작업 시작 단계에서 과도하게 적용되어 실제 업무 진행을 방해함
- 사용자가 같은 지침의 예외 또는 부적합을 반복적으로 지적함
- 기존 지침 또는 새로 반영한 지침과 충돌함
- 도구, 파일 구조, 외부 서비스, 담당 체계가 바뀌어 절차나 경로가 맞지 않음
- 문안이 너무 일반적이어서 실제 검토 품질을 높이지 못함
- 개인정보, 보안, 책임범위 측면에서 새로운 위험을 만듦

등록 후 조치는 다음 중 하나로 정한다.

| 조치 | 기준 |
|---|---|
| 수정 | 취지는 유효하나 문안, 적용 조건, 참조 파일을 고치면 계속 쓸 수 있음 |
| 보류 | 일부 작업에는 유효하지만 일반 적용 여부를 더 확인해야 함 |
| 폐기 | 반복 적용 가치가 없거나 부작용이 더 커 공통 지침에서 제거해야 함 |
| 확인 필요 | 사용자 판단, 실제 발송 화면, 최신 도구 상태 등 추가 확인이 필요함 |

폐기 또는 수정 시에는 대상 지침 파일에서 해당 문안을 실제로 제거하거나 고치고, `improvements/stale_review_log.md`와 `improvements/adoption_log.md`에 처리 결과를 남긴다.

## 4. 반영 금지 기준

다음은 공통 지침에 직접 반영하지 않는다.

- 신고자, 민원인, 담당자, 업체의 식별 정보
- 내부 문서번호, 결재선, 비공개 검토자료의 구체 내용
- 특정 사건에만 맞는 법령 해석 또는 사실 판단
- 사용자가 일회성으로 요청한 문체나 형식
- 출처가 불확실한 외부 정보
- 검증되지 않은 도구 사용법
- 외부 서비스로 자료를 보내는 절차 중 승인 기준이 빠진 내용

## 5. 마무리 보고 방식

지속 개선 루프를 적용한 경우 최종 답변에는 다음을 간단히 보고한다.

1. 추출한 반복 교훈
2. 공통 지침 반영 여부
3. 반영한 파일 또는 후보 등록 위치
4. 제외한 사건 고유 정보
5. 다음 유사 작업에서 확인할 점
