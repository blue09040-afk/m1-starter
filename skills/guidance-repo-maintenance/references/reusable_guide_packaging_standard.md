# 재사용 지침·키트 패키징 표준

## 1. 목적

공통 지침, 실행 키트, 반복 프롬프트를 새로 만들거나 크게 개정할 때 적용하는 최소 구조 기준이다. 사건별 판단이나 일회성 자료가 공통 지침에 섞이지 않도록 하고, 다음 작업자가 같은 흐름을 재사용할 수 있게 만드는 데 목적이 있다.

## 2. 적용 대상

- 새 실행 키트 추가
- 기존 `tools/PDF_READING_KIT`, `tools/HWPX_READING_KIT` 수준의 키트 개정
- 반복 사용할 업무 지침 추가
- 여러 사건에 반복 적용할 프롬프트 또는 템플릿 추가
- 외부 공유 또는 다른 작업 폴더로 복사할 지침 세트 정리

단일 사건 산출물, 일회성 검토 메모, 특정 담당자 정보, 특정 사건의 사실관계는 이 표준의 대상이 아니다. 해당 내용은 사건 폴더의 산출물이나 `HANDOFF_SUMMARY.md`에 남긴다.

## 3. 권장 구조

새 키트나 큰 지침은 가능한 범위에서 다음 역할을 분리한다.

| 구성 | 역할 |
|---|---|
| 진입 지침 | 사람이 먼저 읽을 개요와 적용 조건 |
| 실행 지침 | Codex 또는 작업자가 실제로 따라야 할 단계 |
| `guides/` | 상세 판단 기준, 실패 대응, 검증 기준 |
| `tools/` | 실행 스크립트 또는 보조 도구 |
| `prompts/` 또는 `templates/` | 반복 입력문, 산출물 양식 |
| `examples/` | 민감정보가 제거된 예시 |
| `output/` | 실행 결과물. 공유본에는 원칙적으로 포함하지 않음 |
| `HANDOFF.md` 또는 `HANDOFF_SUMMARY.md` | 이전 작업 이력과 다음 작업 순서 |

이 저장소 안의 하위 키트는 루트 `AGENTS.md`와 혼동되지 않도록 일반명 `AGENTS.md` 대신 `pdf_agents.md`, `hwp_agents.md`처럼 키트명을 드러내는 진입 파일을 사용한다.

## 4. 문서 작성 기준

1. 먼저 적용 조건을 적는다.
2. 그다음 기본 실행 순서를 적는다.
3. 실패 가능성이 큰 도구는 실패 유형과 대체 절차를 함께 적는다.
4. 최종 산출물, 로그, 검증 산출물의 기본 위치를 정한다.
5. 외부 서비스 전송, API 키, 개인정보, 비공개 자료 처리 기준을 별도 항목으로 둔다.
6. 사건 고유 사실, 담당자 실명, 내부 문서번호, 일회성 판단은 예시로도 넣지 않는다.
7. 예시가 필요하면 가명, 축약 주소, 임의 문서번호를 사용하고 실제 사건 자료와 구분한다.

### 4.1 정본과 중복 방지

- 새 규칙을 쓰기 전에 `AGENTS.md`, `README.md`, `guides/`, `skills/`, `prompts/`에서 같은 취지의 기존 규칙을 검색한다.
- 이 절의 역할표를 지침 계층 관리의 정본으로 삼는다. 라우팅·신뢰 경계는 `AGENTS.md`, 사람용 운영 안내는 `README.md`, 공통 행정 판단은 `BASE_INSTRUCTIONS.md`, 특정 업무의 실행 절차는 해당 스킬, 상세 절차는 그 스킬의 `references/`, 반복 입력문은 `prompts/`가 맡는다.
- 같은 규칙을 여러 계층에 전문으로 복사하지 않는다. 다른 계층에는 적용 조건, 짧은 요약과 정본 경로만 남긴다.
- 중복 문구가 충돌하면 둘을 합쳐 새 규칙을 만들지 말고, 현재 상위 실행정책과 사용자 요청을 확인한 뒤 역할에 맞는 정본만 수정한다.

## 5. 출처·조사 산출물 기준

법령, 정책, 통계, 공식 안내, 기술자료처럼 외부 출처 확인이 중요한 작업은 필요한 범위에서 다음 산출물을 둔다.

| 산출물 | 내용 |
|---|---|
| `source_log.md` | 확인한 공식 출처, 확인일, 핵심 근거 |
| `failed_sources.md` | 접속 실패, 원문 미확인, 유료·권한 제한 자료 |
| `extracts/` | 원문에서 필요한 범위로 발췌한 근거 |
| `quality_report.md` | 출처 신뢰도, 남은 확인 필요, 결론 위험 |

사건 처리 중 모든 작업에 위 파일을 기계적으로 만들 필요는 없다. 다만 최신 법령·정책 확인이 결론에 직접 영향을 주거나, 다음 대화방에서 근거를 이어 확인해야 하면 출처 로그를 남긴다.

## 6. 공유·공개 전 점검

지침 세트나 키트를 다른 폴더로 복사하거나 외부 공유하기 전에는 다음을 확인한다.

- 현재 기본지침 폴더는 개인용 실제 운영본으로 취급하고, 그 자체를 공유 패키지로 보지 않는다.
- 공유본은 사용자가 명시적으로 요청한 때에만 그 시점의 별도 폴더 또는 ZIP으로 한 번 생성한다. 상시 유지·갱신하는 공유 폴더나 자동 배포 작업은 두지 않으며, 다음 배포 때는 운영본에서 새로 묶는다.
- 사용자가 포함 범위를 따로 정하지 않으면 `AGENTS.md`, `README.md`, `guides/`, `skills/`, `prompts/`와 실행에 꼭 필요한 경량 `tools/` 파일만 후보로 삼는다. `improvements/`, `LLM_Wiki/`, `work/`, 테스트·벤치마크·백업·설치본·개인 설정은 기본 제외한다.
- 운영본을 통째로 복사하거나 운영본의 `.env`와 산출물을 삭제해 공유본으로 바꾸지 않는다. 별도 공유 폴더에서 아래 항목을 제외·비식별화하고 최종 점검한다.

- 실제 민원자료, 신고자료, 감사자료, 내부 공문 원문이 포함되어 있지 않은가
- 성명, 연락처, 주소 세부정보, 문서번호, 결재선, 담당자 개인 정보가 남아 있지 않은가
- `.env`, API 키, 토큰, 쿠키, 인증 파일이 포함되어 있지 않은가
- `output/`, `_validation/`, 변환 로그, OCR 결과, 임시 압축 해제 폴더에 민감정보가 남아 있지 않은가
- HWPX 작업본의 `Preview/PrvText.txt`, `Contents/section*.xml`, `BinData/`에 실제 사건 정보가 남아 있지 않은가
- 설치 파일, 다운로드 ZIP, 대용량 임시 파일을 불필요하게 포함하지 않았는가
- 설치된 도구를 보관하는 경우 보관 이유와 재설치 경로가 안내되어 있는가
- 웹·문서·OCR·로그에서 가져온 예시에 기존 지침 무시, 비밀 공개, 명령 실행, 권한 변경 또는 외부 전송을 요구하는 비신뢰 지시문이 섞여 있지 않은가

## 7. 기존 지침 연결 기준

- PDF 처리 도구는 `tools/PDF_READING_KIT`를 우선 실행 경로로 둔다.
- HWP 처리 도구는 `tools/HWPX_READING_KIT`를 우선 실행 경로로 둔다.
- 문안 작성과 재검토는 MD 기준본을 우선한다.
- 최종 HWPX, PDF, XLSX 등 바이너리 산출물은 사용자가 요청했거나 제출 형식상 필요한 경우에만 만든다.
- 공통 지침을 고칠 때는 `README.md`, `AGENTS.md`, 관련 `guides/`와 스킬의 참조가 함께 맞는지 확인하되, 같은 규칙의 전문을 여러 파일에 복제하지 않는다.
