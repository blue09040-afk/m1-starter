# GitHub PDF 원본 획득·판독 handoff

## 1. 목적

GitHub 저장소, 특히 인증이 필요한 private 저장소에 있는 PDF를 기존 Markdown/OCR 추출본만으로 단정하지 않고 원본까지 확인하기 위한 절차다. 이 문서는 PDF 읽기 정본인 `pdf-reading-kit`의 source-acquisition reference이며, 사건 고유 자료나 저장소 이름을 고정하지 않는다.

## 2. 원본 확인 트리거

다음 중 하나면 추출 Markdown을 1차 판독 자료로만 사용하고 원본 PDF를 확인한다.

- 표의 행·열 관계, 들여쓰기, 페이지 경계 또는 항목 대응관계가 결론에 영향을 주는 경우
- 사진·도면·지도·직인·서명·결재선·이미지 캡처 등 비텍스트 요소가 필요한 경우
- 추출본에 누락·깨짐·순서 뒤섞임·빈 페이지 의심이 있는 경우
- 날짜·수치·문서번호·요구사항처럼 정확한 원문 확인이 필요한 부분이 모호한 경우
- 서로 다른 추출본 또는 담당부서 자료와 원문이 상충할 가능성이 있는 경우
- 추출본이 아예 없거나 신뢰도를 확인할 수 없는 경우

추출본이 충분히 명확하고 원문 레이아웃이나 비텍스트 요소가 판단에 영향을 주지 않으면 매번 PDF 전체를 다시 열 필요는 없다.

## 3. private GitHub PDF 획득

연결된 GitHub MCP의 `fetch_file`이 `encoding: "base64"`를 지원하면 다음 순서를 우선한다.

1. 저장소와 PDF 경로를 확정한다.
2. `fetch_file(repository_full_name, path, encoding="base64")`로 파일을 읽는다.
3. 반환값의 `encoding`이 `base64`인지, `content`가 비어 있지 않은지 확인한다.
4. Base64 본문은 사용자 응답이나 로그에 출력하지 않고 실행환경으로 전달한다.
5. Base64를 디코딩해 원본 PDF 바이트를 복원한다.
6. 가능한 경우 아래 무결성 검사를 수행한다.
   - 디코딩 바이트 수
   - 시작 헤더 `%PDF-`
   - 종료부 `%%EOF`
   - 반환된 Git blob SHA와 복원 바이트로 계산한 Git blob SHA의 일치 여부
7. 복원한 PDF를 로컬 PDF 파서 또는 승인된 판독 경로로 읽고, 필요하면 관련 페이지만 렌더링해 시각 확인한다.

Git blob SHA는 개념적으로 `SHA1("blob " + byte_length + "\0" + raw_bytes)`로 계산한다.

## 4. 도구별 실패 분류

- 일반 GitHub `fetch` 또는 Contents API wrapper가 `UTF-8 only`, `non-UTF-8 rejected` 등으로 실패해도 이를 PDF 원본 접근 불가로 단정하지 않는다. 먼저 `fetch_file(..., encoding="base64")` 지원 여부를 확인한다.
- GitHub MCP에서 원본 Base64는 받았지만 현재 Chat 실행환경이 그 바이트를 로컬 파일로 materialize하지 못하는 경우, 상태를 `원본 획득 성공 / 로컬 handoff 제한`으로 구분한다.
- private 저장소의 raw/download URL을 Web·Acrobat 등 다른 도구가 같은 인증으로 읽을 것이라고 가정하지 않는다.
- private PDF를 읽기 위해 공개 임시 URL이나 공개 호스팅으로 우회하지 않는다.
- 파일이 크거나 MCP 응답 제한·잘림이 의심되면 작은 PDF의 성공 경험을 일반화하지 않는다. 파일 크기·반환 완전성을 확인하고, 지원되는 authenticated file-reference/download 경로, 로컬 Codex 환경, 또는 사용자가 직접 제공한 원본을 사용한다.

## 5. 판독 순서

원본 PDF를 로컬로 materialize할 수 있으면 다음 순서를 따른다.

1. 파일 형식·페이지 수·암호화 여부를 확인한다.
2. 텍스트 PDF는 Kordoc parse-only 주 경로를 적용한다.
3. 추출 결과와 기존 Markdown을 대조한다.
4. 모호한 표·이미지·도면·직인·서명·페이지 배치는 필요한 페이지만 렌더링해 원본 화면으로 확인한다.
5. 이미지 PDF 또는 누락 페이지는 `pdf-reading-kit`의 선택적 OCR 규칙을 따른다.
6. 날짜·수치·고유명사·문서번호·법령 인용처럼 결론에 직접 영향을 주는 값은 원본 화면 또는 신뢰 가능한 원문 추출로 재확인한다.

## 6. 보안·개인정보 경계

- GitHub MCP 인증은 그 커넥터 내부의 repository access에만 사용된다고 보고, 다른 Web·Acrobat·OCR 도구와 인증이 공유된다고 가정하지 않는다.
- Base64 payload, PDF 원본 바이트, 임시 렌더링, OCR 결과를 재사용 지침·공유 패키지·LLM Wiki에 넣지 않는다.
- 민원서류, 개인정보 포함 문서, 비공개 내부자료는 외부 OCR·변환 서비스 전송 전에 별도 사용자 승인을 받는다.
- 원본 확인을 위해 만든 임시 파일·페이지 이미지는 작업 후 정리하거나 비공유 사건 작업경로에만 보관한다.

## 7. 보고 문구

성공과 실패를 다음처럼 구분한다.

- `원본 PDF 확인 완료`: 원본 바이트를 획득하고 실제 텍스트 또는 페이지 화면까지 확인한 경우
- `원본 획득 완료 / 판독 제한`: Base64 원본과 무결성은 확인했지만 현재 실행환경에서 PDF 파싱·렌더링 handoff가 불가능한 경우
- `추출본 기준 잠정 판단`: 원본 확인이 필요하지만 현재 원본을 읽지 못해 기존 Markdown/OCR만으로 조건부 판단한 경우
- `원본 접근 실패`: authenticated Base64 경로 등 사용 가능한 원본 획득 경로 자체가 실패한 경우

단순히 generic fetch가 바이너리를 거절했다는 이유만으로 마지막 상태를 사용하지 않는다.
