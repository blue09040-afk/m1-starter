# 공익신고 사건 처리 절차

이 문서는 공익신고 대상성 판단 이후의 반복 업무를 다룬다. 사건의 실제 사실·법령·담당부서·기한은 매 건 원자료에서 다시 확인한다.

## 1. 시작과 단계 판별

1. 현재 자료와 `HANDOFF_SUMMARY.md`의 사건번호·일자·신고내용이 일치하는지 확인한다.
2. 현재 작업을 `접수·소관 검토`, `담당부서 의견 및 조사결과 요청`, `담당부서 회신 검토`, `신고자 조사결과 통보`, `국민권익위원회 조사결과 회신` 중 하나로 분류한다.
3. 신고내용, 공식 접수·이송문, 담당부서 회신, 사용자가 지정한 최신 기준 문안 순으로 현재 단계에 필요한 원자료를 식별한다.
4. 확인된 사실, 신고인의 주장, 담당부서 의견, 추가 확인 필요사항을 분리한다.

자료가 충돌하면 사용자가 현재 세션에서 확정한 값, 현재 사건의 공식 접수·이송 정보, 신고 원문, 담당부서 공식 회신과 증빙, 사용자가 지정한 최신 기준 문안 순으로 대조한다. 샘플은 구조·문체 참고용이며 사건 사실의 근거가 아니다.

## 2. 단계별 처리

### 접수·소관 검토

- 공익신고, 일반 민원·감사 참고, 타 기관·별도 절차, 보완 필요, 혼합 사안을 쟁점별로 구분한다.
- 공익침해행위 대상 법률, 처분 가능성, 관할과 위임 관계, 신고자 보호·비밀보장 범위를 확인한다.
- 구조 참고는 `templates/intake_jurisdiction_review_masked_example.md`를 사용한다.

### 담당부서 의견 및 조사결과 요청

- 접수경로, 사건번호, 주요 신고내용, 접수일, 회신기한, 붙임을 원문에서 확인한다.
- 별도로 확정된 회신기한이 없으면 **문안 작성일로부터 1개월**을 기본 실무값으로 사용한다. 외부기관이 정한 더 이른 기한, 사건별 긴급성 또는 사용자가 확정한 기한이 있으면 그 값을 우선한다.
- 기본 공문은 `공익신고 검토 결과 및 위반 의혹 요약 → 소관 판단 및 조사결과 제출 요청 → 접수경로·접수번호·주요내용·접수일자·신고대상 → 신고자 비밀유지 → 붙임`의 간결한 흐름으로 작성한다.
- 신고서·심사의견서·증거자료가 붙임으로 전달되는 일반 사건에서는 세부 법조문별 조사사항과 자료요구를 본문에 장문으로 다시 열거하지 않는다. 사건별로 꼭 필요한 추가 확인사항이 있을 때만 본문을 확장한다.
- 신고자 비밀보장과 조사과정 유의사항을 포함하고, 신고내용과 개인정보는 업무상 필요한 최소 범위만 전달한다.
- 신고자 신분공개 동의 여부, 신고자 직접 연락 제한 등은 원자료에서 실제 확인되고 담당부서 조사에 필요한 경우에만 추가한다. 감사부서에도 신고자 정보가 제공되지 않은 경우에는 해당 상태를 추정하여 문안에 넣지 않는다.
- 기본 문안은 `templates/department_opinion_request_standard_masked_example.md`를 사용한다.

### 담당부서 회신 검토

- 신고 쟁점에 실질적으로 답했는지, 조사·점검 근거와 증빙이 있는지 확인한다.
- 조치가 예정·진행·완료 중 어디에 해당하는지 구분한다.
- 확인 사실과 부서 판단, 책임·위법·고의 평가를 분리하고 자료보다 강한 단정은 완화한다.
- 누락, 내부 모순, 사건번호·날짜·법령·담당부서 착오와 신고자에게 통지할 수 없는 개인정보·수사정보·내부정보를 점검한다.
- 구조 참고는 `templates/department_reply_review_masked_example.md`를 사용한다.

### 신고자 조사결과 통보

- 신고인이 조사 범위, 판단, 조치상태와 이의신청 필요성을 이해할 수 있을 정도로 구체적으로 작성한다.
- 기본 문단은 `인사말 → 신고내용 요약 → 쟁점별 법령·현황·판단·조치 안내 → 해당하는 경우 이의신청·보상/포상 안내 → 담당부서 문의` 순서로 구성한다. 개별 쟁점에서는 `관련 법령·적용 기준 → 조사 경위·확인 사실 → 관계인 소명·증빙 및 판단 → 실제 조치·향후 대응`의 문단 흐름을 우선 고려하고, 사건에 맞게 합치거나 생략할 수 있다.
- 이의신청·보상/포상 안내는 절차별 법적 요건과 통지주체·기산점·제출처를 확인하여 적용한다. 청렴포털을 통한 접수 사실만으로 국민권익위원회 이의신청 절차를 일률적으로 기재하지 않는다.
- 확인되지 않은 사실이나 담당부서 회신 범위를 넘어선 위법·책임 판단을 새로 추가하지 않는다.
- 신고자 통지용 문안과 불특정 다수 공개용 문안을 구분한다.
- 문안·번호체계 참고는 `templates/reporter_result_notice_masked_example.md`를 사용한다.

### 국민권익위원회 조사결과 회신

먼저 사용자가 요청한 산출물이 **국민권익위원회에 보내는 시행 공문**인지, 그 공문에 붙이는 **조사결과 제출용 서식·HWPX**인지 구분한다. 두 산출물은 역할과 형식이 다르므로 같은 샘플을 사용하지 않는다.

#### A. 국민권익위원회 시행 공문

- 기본 골격은 `1. 관련문서 → 2. 조사결과 제출 문장 → 가. 공익신고 개요 → 붙임` 순으로 정리한다.
- `공익신고 개요`에는 현재 사건에서 확인된 `접수번호`, `신고제목`, `조사일자`, `조사결과`를 적는다.
- `조사결과`는 세부 조사경위와 법리를 장문으로 반복하지 않고 **위반 확인 여부와 주요 조치상태**를 중심으로 1~3문장으로 압축한다.
- 사건번호, 수신부서, 관련문서번호·시행일, 붙임 명칭·부수는 원자료에서 확인한 값만 사용한다.
- 공문에 기재할 `조사일자`는 **신고자에게 조사결과를 실제 통보한 날짜**를 사용한다. 현장점검일, 담당부서 회신일, 내부 검토일로 대체하지 않는다.
- 실제 제출하지 않는 붙임을 샘플에 있다는 이유로 임의로 추가하지 않는다.
- 사용자가 현재 사건의 확정 실무 샘플을 지정했다면 그 샘플의 문단 순서와 표제를 우선하고, 없으면 `templates/acrc_result_official_letter_masked_example.md`를 사용한다.

#### B. 국민권익위원회 제출용 조사결과 서식·빠른 HWPX

- 붙임 서식의 입력 구조는 시행 공문의 문안 구조와 별개로 관리한다.
- 기본 개조식은 `templates/acrc_result_notice_flat_masked_example.md`, 둘 이상의 확인 사실에 서로 다른 조치·진행상황이 대응할 때는 `templates/acrc_result_notice_two_level_masked_example.md`를 사용한다.
- 위반이 확인되지 않은 여러 쟁점은 정확한 경우 `그 밖의 신고내용: 관계 법령 위반사항 미확인`처럼 통합할 수 있다. 소관 제외, 일부 판단, 재조사 필요 등 별도 사유는 통합하지 않는다.
- 제출용 양식의 `신고자통보일`은 **신고자에게 조사결과를 실제 통보한 날짜**를 사용한다. 현장점검일, 담당부서 회신일, 내부 검토일로 대체하지 않는다.
- HWPX 생성·치환은 `hwp-hwpx-processing`의 빠른 경로를 적용하되, 구조 예시의 `## 필드명`을 시행 공문 본문으로 옮기지 않는다.

## 3. 문안·샘플·사건 교체 경계

- 실제 처리부서가 둘 이상이면 소제목에 해당 부서를 표시하고, 모든 쟁점을 한 부서가 처리하면 같은 부서명을 반복하지 않을 수 있다.
- 문안 기준본은 Markdown으로 둔다. HWPX 반영은 `hwp-hwpx-processing`을 적용한다.
- 이 스킬의 Markdown 예시는 비식별 재사용 예시다. `구조 예시`는 문단·필드 구조만, `문안 예시`는 확인된 범위의 문체·문장 연결까지 참고한다. 어느 경우에도 사건 사실의 근거로 사용하지 않는다.
- 현재 업무의 기본 예시는 `templates/SAMPLE_CATALOG.md`에서 선택한다. 신규·교체는 `skills/guidance-repo-maintenance/references/deidentified_sample_publishing_standard.md`를 적용한다.
- 결재·발송 확정본은 사건 폴더의 비공유 참조로만 보존한다. 재사용하려면 별도 복제본의 문서속성, 본문, 표·글상자, 미리보기, 패키지 XML, 삽입 이미지와 잔존 개인정보를 검사한 뒤 비식별 Markdown 예시로 반영한다.
- `새 사건으로 교체`, `새 건으로 교체`, `사건 교체` 요청은 현재 사건의 자료와 산출물을 하나의 날짜·사건번호 보관 폴더로 보존 이동한다는 뜻이다. 삭제·덮어쓰기를 하지 않고, 잠김·충돌·귀속 불명확 자료는 이동하지 않는다.
- 이전 사건 보관 폴더와 비공유 참조본은 새 사건 판별에서 제외하고 `HANDOFF_SUMMARY.md`는 현재 사건과 일치할 때만 사용한다.

## 4. 사건 마무리·보존 정리와 다음 사건 준비

사용자가 `결재를 올렸어`, `결재 상신했어`, `발송했어`, `마무리하자`, `작업 종료`와 같은 종료 표현과 함께 **폴더·파일 정리** 또는 **다음 사건 준비**를 요청하면, `새 사건으로 교체`라는 표현이 없어도 사건자료를 보존 정리한다. 정리 요청 자체를 외부 이관 요청으로 해석하지 않는다.

1. 실제 파일과 `HANDOFF_SUMMARY.md`의 사건번호·단계가 일치하는지 확인하고, 상태를 `결재 상신`, `결재 완료`, `시행·발송 완료`로 구분한다. 확인되지 않은 후속 상태로 승격하지 않는다.
2. 정리 위치와 외부 이관 여부는 `guides/BASE_INSTRUCTIONS.md` 제8절의 공통 원칙을 따른다. 외부 보관 폴더나 처리완료 사례가 이미 있어도 자동 이관 근거로 삼지 않는다.
3. 현재 작업폴더 바로 아래에 충돌 없는 `90_교체대상_이전사건_<YYYYMMDD>_<사건번호>` 폴더를 만들고, 해당 사건의 고유 폴더·최종본·검토 산출물을 먼저 보존 이동한다. 사용자가 외부 이관을 명시한 경우에만 그 지정 위치를 사용한다. `HANDOFF_SUMMARY.md`와 자료목록은 결과·잔류·실패 항목을 반영하기 위해 활성 루트에 잠시 남기고, 공통 지침·샘플·도구·저장소 설정과 다른 진행 사건은 그대로 둔다.
4. 이동 전에는 원본과 대상의 절대경로, 대상의 충돌 여부, 이동 대상과 파일 수를 확인한다. 기본 대상은 현재 작업폴더 안에 있어야 하며, 외부 이관을 명시한 경우에는 사용자가 지정한 범위 안인지 확인한다. 외부 대상이 특정되지 않으면 제8절의 공통 원칙에 따라 해당 이동만 보류하고 확인을 요청한다. 삭제·덮어쓰기·충돌 우회는 하지 않는다.
5. 잠김·충돌·귀속 불명확 자료는 강제 종료하거나 임의 이동하지 않는다. 필요한 경우 동일 해시의 보존 사본을 먼저 확인하고, 이동 실패·잔류 위치·후속 정리 방법을 `HANDOFF_SUMMARY.md`에 기록한다.
6. 사건 고유자료 정리 결과가 확정되면 `HANDOFF_SUMMARY.md`와 자료목록에 실제 보관 경로, 처리 상태, 기준 최종본과 해시, 폴더별 자료 성격·파일 수, 남은 확인사항과 이동 실패를 기록한다. 결재 상신본은 결재 완료·시행본 또는 공용 샘플로 표현하지 않는다. 기록을 마친 두 파일은 같은 보관 폴더로 마지막에 보존 이동한다. 사용자가 나중에 원 사건 폴더와 통합하여 최종 이관하는 단계는 별도로 둔다.
7. 사건 고유자료와 갱신된 `HANDOFF_SUMMARY.md`·자료목록의 보존 이동이 성공한 뒤에 활성 루트의 다음 사건용 `00_결재준비`, `01_신고 접수`, `02_담당부서회신`, `03_검토작업`을 준비한다. 없는 폴더만 새로 만들고, 다른 진행 사건 자료가 남아 있는 기존 표준 폴더는 비우거나 재생성하지 않고 그대로 둔다.
8. 종료 검증에서는 보관 폴더의 파일 수, 기준 최종본 해시와 필수 패키지 구성, 인수인계·자료목록 존재를 확인한다. 보관 폴더와 다른 진행 사건을 제외한 활성 작업영역에 정리 대상 사건자료가 남지 않았는지 확인하고, 새로 만든 표준 폴더에 한해 파일·하위폴더가 0건인지 검증한다. 기존 표준 폴더에 남긴 다른 진행 사건 자료의 위치는 `HANDOFF_SUMMARY.md`에 기록한다.
