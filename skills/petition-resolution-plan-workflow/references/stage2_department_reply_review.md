# 진정민원 2단계 담당부서 회신 검토 및 민원인 답변 기준

## 1. 목적과 적용 범위

이 기준은 진정민원 1단계에서 요청한 `진정사항 관련 추진내용 및 향후 해소계획`에 대해 담당부서의 회신 또는 관련 증빙이 도착한 뒤, 그 충실성과 근거를 검토하고 필요한 보완을 거쳐 민원인 답변서를 작성하는 2단계 업무에 적용한다.

다음 경우에는 이 경로를 사용하지 않는다.

- 담당부서의 이번 회신이 아직 없는 경우: `stage1_department_resolution_plan_request.md`
- 국민권익위원회·도권익위원회 요청에 따라 설명자료를 제출하거나 처리결과를 통보하는 경우: `acrc-grievance-complaint-workflow`
- 공익신고 대상성·조사·결과통보를 검토하는 경우: `public-interest-report-review`
- 선행 해소계획 요청 절차 없이 일반민원 답변서만 작성하는 경우: `admin-document-base-review`

담당부서 회신이 일부 쟁점에만 답했거나 증빙이 부족하더라도 1단계로 되돌리지 않는다. 2단계 안에서 보완요청과 부분 재검증을 수행한다.

## 2. 자료 우선순위와 기준본

내용 판단에는 다음 순서를 적용한다.

1. 사용자가 현재 대화에서 명시적으로 확정·수정한 사항
2. 이번 진정민원 원문과 첨부자료
3. 1단계 해소계획 요청문과 담당부서 회신
4. 회신에 첨부되거나 이후 보완 제출된 증빙
5. 이번 민원과 직접 연결되는 기존 수·발신 민원과 후속조치 기록
6. 필요한 범위에서 확인한 현행 공식 법령·기준·공개자료

답변서 형식에는 사용자가 지정한 현재 사건의 최종 실무 서식을 우선한다. `templates/SAMPLE_CATALOG.md`의 예시는 구조 선택을 돕는 자료일 뿐 사건 사실·법령·책임 판단의 근거가 아니다.

## 3. 먼저 만드는 쟁점·근거 대조표

문안 작성 전에 각 독립 쟁점을 다음 항목으로 대조한다. 형식은 표나 구조화된 목록 중 작업에 맞는 것을 선택할 수 있다.

| 항목 | 기록할 내용 |
|---|---|
| 쟁점·요구 | 민원인이 문제 삼은 행위와 요구사항 |
| 기존 처리 | 앞선 회신, 당시 설명, 예고한 후속조치 |
| 1단계 확인요청 | 담당부서에 확인하도록 한 사실·근거·기록·계획 |
| 담당부서 답변 | 이번 회신의 구체적 설명과 판단 |
| 제출 증빙 | 답변을 직접 뒷받침하는 문서·수치·사진·시스템 기록 등 |
| 검증 결과 | 확인됨 / 일부 확인 / 상충 / 미확인 |
| 남은 조치 | 보완요청 / 자체 확인 / 타 부서·기관 확인 / 답변 가능 |
| 답변 반영 | 민원인에게 설명할 결론, 한계, 향후조치 |

같은 자료가 여러 쟁점에 관련되더라도 각 쟁점의 답변 충족 여부를 따로 판단한다. 민원인의 독립 요구를 담당부서 회신 문단 수에 맞춰 합치거나 누락하지 않는다.

## 4. 담당부서 회신의 충실성 판단

다음 순서로 점검한다.

1. **답변성**: 1단계에서 확인을 요청한 핵심 질문에 실제로 답했는가
2. **구체성**: 누가·언제·무엇을·어떤 방법과 근거로 확인하거나 조치했는지 필요한 범위에서 특정되는가
3. **증빙성**: 주장이나 평가를 뒷받침하는 동시기 기록 또는 객관자료가 있는가
4. **정합성**: 회신 본문, 첨부자료, 기존 회신, 공식자료 사이에 모순이 없는가
5. **상태성**: 예정·진행·완료·미실시가 구분되고 기준시점이 분명한가
6. **소관성**: 담당부서가 설명할 권한과 자료가 있는 범위를 넘겨 단정하지 않았는가
7. **답변 완전성**: 민원인의 독립 쟁점과 요구사항이 각각 답변 가능한 상태인가

담당부서가 `검토하였다`, `문제가 없다`, `조치하였다`고 적었다는 사실만으로 그 행위나 판단이 입증된 것으로 보지 않는다. 사건 결론에 중요한 경우에는 실제 검토기록, 계산·분석자료, 현장확인 기록, 내부결재, 협의자료, 조치 결과 등과 대조한다.

## 5. 증빙과 수치 검증

- 문서의 작성일·기준일·대상기간·작성주체·적용대상이 현재 쟁점과 맞는지 확인한다.
- 수치가 결론에 영향을 주면 단위, 산식, 집계기간, 누적값과 현재값, 반올림·근사 여부를 구분하고 가능한 범위에서 재계산한다.
- 사진·영상·녹음·OCR·추출문은 원자료의 맥락과 판독 신뢰도를 확인한다. 판독이 불분명한 식별정보나 법률용어를 확정값으로 옮기지 않는다.
- 공개자료나 법령은 변동 가능성이 결론에 영향을 줄 때 현행 공식 출처와 확인시점을 남긴다.
- 증빙이 없는 부분은 `자료상 확인되지 않음`과 `사실이 아님`을 구분한다.

## 6. 보완요청과 부분 재검증

### 6.1 보완이 필요한 경우

다음 중 하나가 답변 결론을 바꿀 수 있으면 필요한 최소 범위로 보완한다.

- 핵심 쟁점이 누락되었거나 질문과 다른 일반론만 회신한 경우
- 결론적 표현은 있으나 이를 확인할 기록이나 산출근거가 없는 경우
- 회신과 첨부자료 또는 기존 기록이 상충하는 경우
- 예고한 후속조치의 현재 상태와 완료 근거가 불명확한 경우
- 담당부서 소관 밖의 쟁점을 해당 부서 답변만으로 종결하려는 경우

보완요청은 `부실하다`고 평가하기보다 `어떤 결론을 판단하기 위해 어떤 사실·기준시점·자료가 필요한지`를 특정한다. 이미 제출된 자료를 다시 요구하지 않는다.

### 6.2 보완을 기다리지 않고 답변할 수 있는 경우

부족한 자료가 주변적이거나, 미확인 한계를 명시해도 핵심 답변이 달라지지 않거나, 추가 자료를 현실적으로 확보할 수 없는 경우에는 그 한계를 밝혀 현재 자료 기준으로 답변할 수 있다. 단, 미확인 사실을 담당부서 설명만으로 확정하지 않는다.

### 6.3 새 자료가 도착한 경우

새 자료가 들어오면 영향을 받는 쟁점과 그에 의존하는 결론만 다시 검증한다. 새 자료가 다른 쟁점의 근거까지 바꾸는 경우에만 검증 범위를 확장한다.

## 7. 작성 전 검증 관문

민원인 답변서 초안을 쓰기 전에 `document-validation-pipeline`을 한 번 적용한다.

최소 확인항목은 다음과 같다.

- 원자료와 추출문·요약의 대응관계
- 민원인의 독립 쟁점과 요구사항 전체 목록
- 담당부서 회신과 증빙의 쟁점별 충족 여부
- 상충·누락·미확인 사실과 보완 필요성
- 감사·민원부서, 담당부서, 타 부서·기관의 권한 경계
- 사실판단·법적 평가·향후조치의 근거 수준
- 선택한 답변서 구조와 결론을 지지하는 검증결과

Codex처럼 파일을 작성할 수 있는 사건 작업 폴더에서는 기본 검증결과를 `_validation/validation_report.md`에 남긴다. 보조표나 재계산 파일은 사건이 복잡하거나 이어서 검토할 필요가 있을 때만 만든다. 일반 Chat에서는 같은 항목을 응답 안의 구조화된 검토결과로 제시하고, 파일을 만들었다고 가정하지 않는다.

## 8. 민원인 답변서 구조 선택

현재 사건의 확정 서식이 있으면 그 구조를 우선한다. 별도 확정 서식이 없으면 `SAMPLE_CATALOG.md`에서 다음 중 하나를 선택한다.

1. **기존 처리 재점검형 — 기본**: 기존 처리경위, 이번 제출자료와 추가 확인, 보완·시정조치, 종합 검토결과가 핵심인 경우
2. **단순 사실확인형**: 단일 쟁점의 사실관계, 검토의견, 향후조치만 간결하게 답할 수 있는 경우
3. **현황 집계·복수부서형**: 여러 부서·기관 답변을 현황표와 쟁점별 항목으로 통합해야 하는 경우
4. **복수쟁점·권한한계형**: 여러 주장에 대해 기존 기록·공개자료·법적 효력 또는 권한 경계를 구분해야 하는 경우

구조를 섞어야 할 때도 민원인이 각 쟁점의 결론과 근거를 찾기 어렵지 않도록 한다. 샘플의 문구나 항목 수를 맞추기 위해 현재 사건에 없는 내용을 만들지 않는다.

## 9. 답변 문안 작성 원칙

- 민원인의 주장은 `귀하께서는 ...를 문제로 제기하셨습니다`처럼 귀속한다.
- 담당부서의 설명은 증빙으로 확인된 사실과 구분한다.
- `현재까지 제출된 자료와 추가 확인 결과`처럼 판단 기준시점을 드러낸다.
- 위법·부당·과실·허위 등을 단정하려면 그 판단을 뒷받침하는 권한과 근거가 있어야 한다.
- 조치 완료, 조치 예정, 검토 중, 담당부서 의견을 서로 바꾸어 쓰지 않는다.
- 공개·제공이 제한되는 자료가 있으면 제한 근거와 답변 가능한 범위를 구분한다.
- 여러 부서의 답변을 통합하더라도 책임주체와 문의처를 혼동하지 않는다.
- 민원인이 이미 아는 접수 경위나 내부 검토과정을 장황하게 재현하지 않고, 쟁점별 결론과 이유를 중심으로 쓴다.

## 10. 작성 후 일치 확인

초안 작성 뒤에는 작성 전 검증결과와 다음 사항만 간단히 대조한다.

- 모든 독립 쟁점과 요구사항에 답했는가
- 검증되지 않은 사실이 확정 표현으로 바뀌지 않았는가
- 보완 전 미확인 사항을 해결된 것처럼 쓰지 않았는가
- 근거보다 강한 법적 평가나 책임 판단을 추가하지 않았는가
- 예정·진행·완료와 기준시점이 유지되었는가
- 선택한 구조가 현재 사건과 확정 서식에 맞는가

문체 수정만으로 근거가 바뀌지 않았다면 실질검증을 반복하지 않는다. 새 증빙, 새 쟁점, 계산 오류, 권한 판단 변경처럼 결론의 기초가 바뀐 경우에만 영향을 받는 범위를 다시 검증한다.

## 11. 기본 출력

사용자가 다른 형식을 지정하지 않으면 다음 순서로 제공한다.

1. 현재 단계와 결정적 자료
2. 쟁점별 회신·증빙 검토결과
3. 보완요청 또는 별도 확인사항 — 실제 필요한 경우만
4. 작성 전 검증결과
5. 민원인 답변서 초안
6. 결재 전 확인사항 — 실제 남은 항목만

사용자가 바로 사용할 최종 문안만 요청하면 내부 대조표와 작업 흔적은 줄이되, 결론에 영향을 주는 미확인·제한사항은 삭제하지 않는다.

## 12. 샘플에서 일반화한 운영 패턴

- 일반 진정민원의 대표 흐름은 `접수 → 1단계 해소계획 요청 → 담당부서 회신·증빙 → 필요한 보완 → 추가 자료 검증 → 민원인 답변`이다.
- 복잡한 사건에서는 기술검토, 수치 재계산, 증빙 유효성 확인, 누락 쟁점 재점검이 별도 작업으로 생길 수 있으나, 최종 결론은 하나의 작성 전 검증결과로 통합한다.
- 권익위·도권익위원회 이송 사건에서 사용된 다부서·다매체 교차검증 방식은 복잡도 대응 참고로만 활용한다. 해당 사건의 외부기관 제출·통보 구조를 일반 진정민원 2단계 형식으로 가져오지 않는다.
- 실제 사례의 사건명, 민원번호, 인명, 주소, 부서·담당자, 연락처, 내부 문서번호, 질병·가족관계, 녹음·영상 내용과 희소한 사실 조합은 공통 지침과 비식별 샘플에 보존하지 않는다.
