# 진정민원 1단계 담당부서 해소계획 요청 기준

## 1. 목적과 적용 범위

이 기준은 감사·민원부서가 진정민원을 접수한 뒤, 현재 민원내용과 필요한 범위의 기존 수·발신 민원자료를 검토하여 소관 담당부서에 `진정사항 관련 추진내용 및 향후 해소계획` 제출을 요청하는 1단계 업무에 적용한다.

다음 경우에는 이 경로를 사용하지 않는다.

- 국민권익위원회·도권익위원회 고충민원 1·2·3단계: `acrc-grievance-complaint-workflow`
- 공익신고 대상성·조사·결과통보: `public-interest-report-review`
- 담당부서의 해소계획 회신과 관련 증빙이 이미 도착한 경우: 이를 `진정민원 2단계`로 예정 구분한다. 2단계의 역할은 담당부서 회신내용을 검토하고 민원인 회신 답변서를 작성하는 것이며, 별도 세부 지침이 확정되기 전까지 `admin-document-base-review`로 개별 검토한다.

## 2. 자료 우선순위

1. 사용자가 현재 대화에서 명시적으로 확정·수정한 기준
2. 이번에 접수된 진정민원 원문과 첨부자료
3. 이번 민원과 직접 연결되는 기존 수·발신 민원, 회신문, 정보공개 회신, 내부 확인자료
4. 사용자가 현재 사건의 기준 샘플로 지정한 확정 서식
5. `templates/SAMPLE_CATALOG.md`가 지정한 비식별 구조 예시

사건 고유 사실은 `m1`에서 찾지 않는다. 샘플은 구조 참고용이며 사실·법령·책임 판단의 근거가 아니다.

## 3. 1단계의 핵심 목적

1단계의 목적은 민원인의 표현을 그대로 담당부서에 전달하거나 감사부서가 먼저 위법·부당 여부를 판단하는 것이 아니다.

다음 두 가지를 동시에 달성한다.

1. 이번 민원의 핵심 문제 제기와 기존 처리 경위를 담당부서가 이해할 수 있을 정도로 압축한다.
2. 담당부서의 회신을 받아야만 확인할 수 있는 사실, 판단과정, 근거기록, 현재 조치상태를 선별하여 구체적으로 묻는다.

따라서 `민원 요약`과 `확인 요구`가 같은 내용을 반복하지 않도록 한다.

다만 압축을 이유로 서로 다른 독립 쟁점이나 요구사항을 삭제하지 않는다. 향후 민원인 회신에서 답변 여부를 달리할 수 있는 쟁점은 유지하되, 실제 담당부서가 답할 수 있는 사항과 감사·민원부서 자체 확인사항, 다른 부서·기관 소관사항을 구분한다.

## 4. `< 민원 내용 및 요청사항 정리 >` 작성 구조

사용자가 별도 구조를 확정하지 않았다면 다음 흐름을 기본으로 한다.

1. **제목**
   - 민원 대상·핵심 쟁점이 드러나는 짧은 제목
2. **현재 민원의 핵심 문제 제기**
   - 민원인이 무엇을 문제 삼고 무엇을 요구하는지 1개 문단으로 정리
3. **기존 처리·회신 경위** — 필요한 경우에만
   - 이번 민원을 이해하거나 확인항목을 특정하는 데 필요한 기존 회신만 압축
   - 기존 답변 전문을 다시 쓰지 않음
4. **현재까지 남은 확인사항**
   - 사실확인·판단근거·관련 기록·조치상태를 필요한 최소 항목으로 묶음
5. **기존 회신에서 약속·예고한 후속조치의 현재 상태** — 해당하는 경우에만
6. **제출 요청 문장**
   - 기본형: `→ 위 사항과 관련하여 실제 업무처리 내용 및 관련 자료를 기준으로 구체적으로 작성하여 제출하여 주시기 바랍니다.`

항목 수를 형식에 맞추기 위해 억지로 늘리지 않는다. 반복되는 질문은 하나로 합친다.

## 5. 박스 외 기존 양식 보존

`진정사항 관련 추진내용 및 향후 해소계획` 서식에서 `< 민원 내용 및 요청사항 정리 >` 외 부분은 사용자가 별도 수정을 요청하지 않는 한 **고정 양식**으로 취급한다.

- `○ 발생 배경`
- `○ 진정(민원) 내용`
- `○ 진정민원 관련 추진경위`
- `□ 진정 내용의 사실여부 및 경과 등`
- `(민원인 주장) / (답변)` 작성란
- 수사·재판·처분 등 사항
- `□ 민원해소를 위한 향후 조치계획 등`
- 확인자·작성자·감사관 귀하·주의문구 등

위 고정 양식을 더 친절하게 만들거나 중복을 줄인다는 이유로 임의 재작성하지 않는다. 1단계 초안의 주된 편집 대상은 박스 안이다.

## 6. 확인사항을 설계하는 방법

### 6.1 담당부서가 실제로 답할 수 있는 사항만 요청하기

민원 원문에 여러 종류의 문제가 함께 있어도 모든 내용을 하나의 담당부서에 넘기지 않는다.

- 소관 담당부서가 실제 업무처리 사실·판단근거·후속조치를 설명할 수 있는 사항 → 해소계획 요청사항으로 정리
- 감사·민원부서의 배부·감사·처리경위 자체가 쟁점인 사항 → 감사·민원부서 자체 확인사항으로 분리
- 다른 부서 또는 다른 기관의 권한·처리가 쟁점인 사항 → 해당 소관으로 분리

담당부서에 답할 권한이나 자료가 없는 사항을 억지로 묻지 않는다. 반대로 담당부서 요청에서 제외했다는 이유로 민원인의 독립 쟁점 자체를 삭제하지 말고, 필요한 경우 별도 확인과제로 남긴다.

### 6.2 답을 이미 알고 있는 질문을 반복하지 않기

공식자료나 사용자가 직접 확인한 신뢰 가능한 자료에서 존재 여부가 충분히 확인된 사항을 담당부서에 다시 `있느냐`고 묻지 않는다. 그 질문이 새로운 사실을 만들어내지 못하면 삭제하거나 더 실질적인 확인항목으로 바꾼다.

예:

- 자료가 실제 제공되고 있다는 점이 이미 확인됨 → `자료가 존재하는지` 재질의하지 않음
- 기존 회신에서 특정 자료를 안내함 → 단순히 `그 자료를 봤는지`만 묻기보다, 판단과정이 쟁점이면 당시 검토를 확인할 수 있는 기록이나 구체적 판단근거를 확인

### 6.3 검토 여부가 쟁점이면 당시 기록을 확인하기

`제대로 검토했는지`를 직접 묻는 문구는 추상적이고 방어적인 답변을 유도할 수 있다. 검토의 실재성과 과정을 확인하려면 다음과 같은 동시기 기록의 작성·보유 여부를 묻는 방식이 더 유효하다.

- 검토보고서
- 내부결재자료
- 업무메모
- 출장·현장확인 기록
- 관계기관 협의자료
- 기술자문·검토요청 및 회신자료
- 그 밖에 당시 판단과정을 확인할 수 있는 기록

단, 실제 사건의 쟁점과 무관한 자료를 포괄적으로 요구하지 않는다.

### 6.4 방법·근거·기록을 구분하기

필요한 경우 다음을 구분한다.

- **방법**: 어떤 방식으로 현장·자료·시스템을 확인했는지
- **근거**: 어떤 사실·수치·조건을 토대로 판단했는지
- **기록**: 그 검토·판단이 당시 어떤 문서나 기록으로 남았는지

같은 질문을 세 표현으로 반복하지 말고, 현재 민원의 핵심 쟁점에 필요한 축만 남긴다.

### 6.5 예정 조치는 현재 상태를 묻기

기존 회신에서 기술자문, 관계기관 협의, 현장점검, 개선조치 등을 `예정`이라고 안내했다면, 이번 민원 시점의 진행 여부·현재 상태·향후 계획을 확인한다. 이미 완료된 조치를 다시 `계획`으로 표현하지 않는다.

## 7. 중립적 문체와 감사부서 경계

- `민원인은 ... 문제를 제기하고 있음`, `... 확인할 필요가 있음`처럼 민원인 주장과 조사 필요를 구분한다.
- 기존 답변이 부족했다거나 담당부서가 형식적으로 처리했다고 감사부서가 선결론한 것처럼 쓰지 않는다.
- `기존 회신 내용을 단순 반복하지 말라`, `부실 답변`, `형식적 처리`처럼 담당부서를 질책하는 뉘앙스의 요청문은 원칙적으로 피한다.
- 필요한 구체성은 비판적 수식어가 아니라 **확인할 사실과 자료를 정확히 특정하는 방식**으로 확보한다.
- 민원인의 단정적 위법·특혜·부당 표현은 확인 전에는 기관의 사실판단으로 바꾸지 않는다.

## 8. 중복 축소 기준

다음 순서로 중복을 줄인다.

1. 같은 문제 제기가 여러 기존 민원에 반복되면 가장 최근 또는 가장 구체적인 형태로 한 번만 정리한다.
2. 기존 회신의 일반론과 민원인의 반박을 각각 장문으로 재현하지 않고, 이번 확인사항을 이해하는 데 필요한 충돌만 남긴다.
3. 하위 고정 양식에서 담당부서가 다시 작성할 `발생 배경`, `추진경위`, `사실 여부`, `향후계획`을 박스 안에서 미리 상세 작성하지 않는다.
4. 세부 질문이 서로 포함관계이면 상위 질문으로 묶는다.
5. 중복을 합친 뒤에도 독립 쟁점별로 담당부서 회신 필요 여부와 별도 확인 필요 여부가 식별되는지 다시 확인한다.

## 9. 작성 전·후 점검

### 작성 전

- 이번 민원 원문이 있는가
- 직접 연결되는 기존 수·발신 자료가 있는가
- 현재 담당부서 회신이 아직 없는 1단계가 맞는가
- 사용자가 지정한 현행 서식이 있는가

### 작성 후

- 민원인 주장과 확인된 사실을 혼합하지 않았는가
- 서로 다른 독립 쟁점을 중복이라는 이유로 삭제하지 않았는가
- 담당부서 요청사항과 감사·민원부서 자체 확인사항, 타 부서·기관 소관사항을 구분했는가
- 이미 확인된 사실을 의미 없이 다시 묻지 않았는가
- `제대로 검토했는지` 같은 추상 질문 대신 확인 가능한 자료·과정으로 바꾸었는가
- 기존 답변을 질책하는 문구가 들어가지 않았는가
- 예정·진행·완료 상태를 구분했는가
- 박스 외 고정 양식을 임의 변경하지 않았는가
- 사건 고유 개인정보와 내부 정보가 불필요하게 노출되지 않았는가
